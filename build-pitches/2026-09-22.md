# Build-Pitch of the Day — 2026-09-22

## Budget-aware self-checkpointing for headless summons (tiered self-compaction, not a fixed threshold)

**Technique.** Instead of relying on the harness's single fixed auto-compact
threshold and generic default summarization prompt, give a long-running
autonomous agent its own tool + tiered thresholds (notice → warning → force)
to decide *when* and *how* to compact itself — with compaction prompts
written for the specific task, so what gets preserved is "current blocker,
what's been tried, what's left" rather than a generic recap. The deeper
point from the research: the right trigger for compacting is semantic (are
we at a safe boundary in the task?), not just numeric (is the buffer 85%
full?).

**Who's doing it.**
- IndyDevDan, ["Self-Compact Pi Agent: ZERO HYPE Agentic Coding Devlog"](https://www.youtube.com/watch?v=3b0U4_02bAE)
  (2026-09-21) — builds a standalone coding agent with a self-compaction
  tool, three threshold levels, per-level custom compaction prompts, and
  human-in-the-loop override commands, explicitly for "long-running
  autonomous agents that operate out the loop" (his multi-agent swarms).
- Corroborating: 3 separate open/closed Claude Code feature requests asking
  for exactly this capability — [#23711](https://github.com/anthropics/claude-code/issues/23711)
  (configurable compact-at-% threshold), [#41818](https://github.com/anthropics/claude-code/issues/41818)
  (same ask), [#71803](https://github.com/anthropics/claude-code/issues/71803)
  (agent-invokable `/compact`) — the last one **closed "not planned"**,
  confirming Claude Code does not ship this natively today.
- Academic backing: ["Self-Compacting Language Model Agents"](https://arxiv.org/pdf/2606.23525)
  (arXiv 2606.23525, 2026) — agents that learn a semantic "safe boundary to
  compact" rule beat fixed-threshold/static-compression baselines on task
  performance and token efficiency. Caution worth building in:
  ["Governance Decay: How Context Compaction Silently Erases Safety
  Constraints in Long-Horizon LLM Agents"](https://arxiv.org/pdf/2606.22528)
  — naive compaction can drop in-context constraints; custom prompts should
  explicitly re-assert standing rules (e.g. "never send 2FA codes headless"),
  not just task state.
- Anthropic's own [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
  independently confirms "compaction isn't sufficient" on its own — the
  fix they recommend is externalized progress-tracking files a new session
  reads on startup. That's the piece Kyle's fleet already does
  (STATUS.md/THREADS.md/HANDOFF.md); what it's *missing* is a forced
  checkpoint-before-death trigger inside a single long summon.

**Evidence it's real.** Cross-checked against Claude Code's own GitHub
issue tracker (real, unresolved community demand — not shipped), a 2026
arXiv paper with actual experimental results favoring semantic over
numeric triggers (not just a demo), and Anthropic's own engineering
writing on the same problem class. Three independent sources converge on
the same gap: fixed-threshold, harness-default compaction is not enough
for agents that run a long time without a human watching.

**Need it serves.** Directly matches a pattern visible in
`~/fleet-optimizer/STATUS.md` right now: the portal-login tickler's
headless summons have independently rediscovered the *same* CDP-attach
hang bug on 2026-09-13, 09-14, 09-19, 09-20, and 09-21 — burning budget
re-deriving a fact already known — and at least one summon died mid-task
with unclear state ("ran out of this summon's token budget mid-Penn-Mutual
… clicked into what looked like a new tab, unverified"). That's a summon
dying without a clean handoff, not a summon running out gracefully. Serves
**priority 2** (AI businesses / the multi-agent unlock: work should carry
forward without Kyle's constant attention — dying mid-task with lost state
is the opposite of that) and indirectly **priority 1** (every mid-task
death that needs a human to untangle costs Kyle's attention).

**Whole-fleet leverage.** Every long-running headless role (fleet-optimizer
summons, ticklers, the dispatcher's `run_task.sh` jobs) shares this same
harness-level gap — a fix at the dispatcher level pays out across all of
them, not just one role.

**Build sketch.** Does NOT duplicate the in-flight session-resume work
(`~/.observer/wiki/agent-os/2026-09-06-checkpoint-resume-claude-role-
sessions-spec.md`, approved, Phase 1 already queued under model-router) —
that restores a *dead* session's exact conversation state. This is about
never dying uncleanly in the first place:
1. In `~/observer-system/scripts/run_task.sh` / `observer/dispatcher.py`,
   add a token/turn-budget watcher next to the existing spend-cap gate
   (`observer/dream/spend_cap.py` already tracks spend — extend the same
   pattern to per-summon budget).
2. At a "warning" threshold (e.g. 70% of the summon's allotted budget),
   inject a forced self-checkpoint prompt: "write your current blocker,
   what you've tried, and what's unverified to STATUS.md/HANDOFF.md before
   continuing" — not a generic compact, a task-state-preserving one.
3. At a "force" threshold, require the checkpoint write to have happened or
   trigger it directly before the summon is allowed to keep running.
4. Test against the exact regression pattern already in STATUS.md: a
   summon that hits the CDP-hang bug should write it once, and future
   summons should read it instead of re-discovering it.

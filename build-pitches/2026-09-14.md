## The find: `claude plugin eval` — Claude Code's native skill/plugin regression-testing framework, and it's already sitting on this machine unused
**Technique.** Anthropic shipped a first-party eval framework for Claude Code
skills and plugins: `claude plugin eval` runs a suite of realistic prompts against
a plugin/skill, scores each with graders (regex, tool-used, tool-order,
file-exists — all free; `llm`/`baseline` bill a judge model), and — critically —
runs each case **with and without** the skill loaded, reporting the delta (Δ) as
the actual measured contribution. Docs state plainly: "If a case scores 1.0 in
both arms, the plugin is not why it passed." `claude plugin eval init` has Claude
read the plugin/skill itself and auto-propose the test cases and graders rather
than requiring them hand-written. Output is a JSON + HTML report, reproducible,
and can gate CI (with a documented per-run cost cap, e.g. $20 USD, to bound the
judge-model spend). There is a parallel, simpler format — `evals/evals.json`,
run via the **skill-creator plugin** — that applies to plain project-level skills
in `.claude/skills/<name>/SKILL.md`, no full plugin packaging required: prompts,
optional input files, and expected behavior, graded in isolated fresh-context
runs, with `grading.json` (pass/fail + evidence) and `benchmark.json` (pass rate,
tokens, time, with-vs-without) as output.

**Who's doing it / timeline.** Official Anthropic release, Claude Code **v2.1.269,
2026-09-11** — three days old. Primary source:
[code.claude.com/docs/en/plugin-evals](https://code.claude.com/docs/en/plugin-evals)
and [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills)
(the skill-creator evals section). Independently corroborated, not a repost:
[MarkTechPost](https://www.marktechpost.com/2026/09/11/anthropic-adds-plugin-evals-to-claude-code-6-grader-types-a-no-plugin-baseline-and-a-ci-gate-for-skills/)
(a real AI-news outlet, not a content farm — names the same 6 grader types, the
no-plugin baseline, and the CI-gate mechanism independently), plus
[explainx.ai](https://www.explainx.ai/blog/claude-plugin-eval-claude-code-guide-2026)
and [aiidelist.com](https://aiidelist.com/blog/claude-code-plugin-eval).

**Evidence it's real, not hype.** The docs are candid about failure modes, not
selling a silver bullet: "usage-limit errors can fake a regression" (cost/quota
noise can look like a behavior regression — a stated caveat, not a hidden one);
the most common real finding per MarkTechPost is "near-zero Δ with failing
tool_used graders" — i.e., **the skill doesn't reliably trigger in natural
conversation, a defect that manifest/schema validation (`claude plugin
validate`) structurally cannot catch.** That is a specific, falsifiable,
independently-reported failure class, not a marketing claim. It requires Claude
Code ≥2.1.269. **Verified directly on this machine:** `claude --version` reports
**2.1.269** — the fleet is already on the exact version this shipped in, zero
upgrade needed. **Also verified:** the `skill-creator` plugin is **already
installed** on this machine
(`~/.claude/plugins/marketplaces/claude-plugins-official/plugins/skill-creator/`)
— the tool to build project-level skill evals is present and unused, not a new
dependency to add. Grepped `~/observer-system` and `~/.claude` for any existing
use of `evals.json` or `claude plugin eval` in the fleet's own skills: zero hits
beyond the plugin's own bundled docs/schema files. Nobody has pointed this at any
of the fleet's own skills yet.

## Need it serves
**Priority 3 — resilience, primary.** This is the closest thing to a direct fix
for the fleet's single most repeated incident *shape* in STATUS.md: automation
that silently stops doing its job (`agent-reply-notify.sh` dark 5 days,
`canonical_checkout_guard.py` not firing on a Bash-tool checkout, a deploy-gate
false-DOWN page, an awk bug that inverted a money reading). None of those are the
same bug, which is exactly why a hand-written guard-by-guard fix doesn't
generalize — but "does this skill still behave the way it did last week, with
receipts" is a generic regression check that applies to all of them the same way.
**Priority 2 — the multi-agent-without-Kyle unlock, secondary.** As the fleet adds
more standing, unattended roles and skills (18 roles in `roles.json`, growing
weekly per STATUS.md), the number of things that can silently regress without
anyone watching grows with it. A reproducible, scored eval that runs on every
skill change is a way to keep trusting autonomy *without* Kyle's attention as the
review mechanism — the whole point of priority 2.

## Whole-fleet leverage
Zero new infrastructure, zero Kyle-tap, zero dependency to install (the CLI
version and the skill-creator plugin are both already present) — this is
authoring test cases against skills that already exist, using a tool already on
the machine. Complementary to, not competing with, the last three pitches:
Docker Sandboxes and Auto Mode limit what a running agent *can* do; session
resume preserves *state* across wakes; this is the only one of the four that
checks whether a skill's *behavior* is still correct after it's been edited —
a distinct axis, and the one the incident log says is currently unmonitored.

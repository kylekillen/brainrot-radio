## Pitch 1 — Claude Code 2.1.216 closed the exact worktree-escape vector that justified the pending Docker Sandboxes pitch, and version currency itself needs to become a monitored fleet health check

**Technique.** Two things shipped together in Claude Code 2.1.216 (released 2026-07-20): (1) resumed background-agent sessions now restore their original prompt and tool restrictions instead of silently reverting to the unrestricted default agent — closing a real permission-escalation bug where "conversation history comes back but the role and tools do not"; (2) subagents running in isolated git worktrees can no longer redirect Git operations into the shared parent checkout via `git -C`, `--git-dir`, `GIT_DIR`, or `GIT_WORK_TREE` — closing the exact escape vector for the "isolated worktree" convention this fleet leans on for every `Agent`/`Workflow` worker dispatch.

**Who's doing it / where it's documented.** This isn't a YouTube technique — it's an Anthropic release, cross-reported independently by three outlets: [Claude Code 2.1.216 Tests Whether Agent Permissions Survive the Handoff (TECHi)](https://www.techi.com/claude-code-update-agent-permissions-worktree-isolation/), a matching mirror at [europesays.com](https://www.europesays.com/ai/112628/), and a full changelog compilation at [wotai.co: Claude Code 2.1.216 — everything that changed since 2.1.186](https://wotai.co/blog/claude-code-2-1-216). All three independently confirm the same two fixes landing in the same release, sourced from Anthropic's own release notes rather than a single blogger's read.

**Evidence it's real.** Cross-checked, not taken on one source's word:
- TECHi's writeup and wotai.co's changelog agree on the mechanism and the version number (2.1.216) for both fixes independently — not one post copying the other's framing.
- I directly ran `claude --version` on this machine: **2.1.220** — four patch releases past the fix, so both vulnerabilities are already closed here. That resolves the FO's open "five-minute check" from its 2026-07-30 scan (`~/fleet-optimizer/STATUS.md`, 2026-07-30 entry) with a confirmed answer, not a restated question.
- The worktree-escape mechanism is exactly the shape of a bug this fleet has independently logged for real: STATUS.md's 2026-07-17 entries ("⚠️ `~/observer-system` IS the deploy," "the canonical-tree edit slips between READ and WRITE, not at intent") and the 2026-07-24/07-25 build-pitches (Docker Sandboxes) were justified specifically by "the current defense is a git-worktree *convention* — discipline, not a mechanism." Anthropic's 2.1.216 fix converts part of that convention into an enforced boundary at the tool layer, for free, just by staying current.

**Need it serves.** Priority 2 (the multi-agent unlock: delegated work carrying forward without Kyle's attention only scales if a background agent's role restriction can't quietly evaporate on resume) and priority 3 (resilience: a permission-scoped reviewer or read-only agent silently regaining full tool access on resume is a live-tree/credential risk, not a hypothetical one). It also directly narrows an open decision already sitting in front of Kyle — the pending Docker Sandboxes pitch — by closing one of the two failure classes it was built to cover.

**Whole-fleet leverage.** Every headless summon, every `/delegate` worker, every role-scoped background agent across the entire fleet inherits both fixes simply by running on a current binary — this is a zero-cost, zero-build security upgrade that applies fleet-wide, not per-project. But it only stays true if the binary stays current: `system-map.md` doesn't record a CLI version today, and the FO found no auto-update mechanism in `~/observer-system/scripts`. A silently-stale binary anywhere in the dispatch launch path (a different machine, a pinned version, a `curl`'d install that never got re-run) would quietly reopen exactly the two holes above with no signal anywhere in the fleet's health surface.

**Build sketch.**
1. Confirmed this session: `claude --version` → `2.1.220`, past both fixes (2.1.216). No immediate action needed on this machine today.
2. Add a version-currency line to the fleet's health surface — `observer-deploy-sync.sh` (`~/observer-system/scripts/observer-deploy-sync.sh`) already runs a health check on every deploy-sync tick; add `claude --version` output alongside it, or record it in `system-map.md`'s regeneration step, so a stale binary shows up as a visible fact rather than an unmonitored one.
3. Re-scope the pending Docker Sandboxes pitch (`build-pitches/2026-07-24.md` Pitch 2, `2026-07-25.md` Pitch 2) in light of this: the worktree git-redirect escape it was partly guarding against is now closed natively. The sandboxing pitch's remaining justification narrows to host filesystem/credential access and network egress — still real, but Kyle should know the goalposts moved before deciding whether the VM-level investment is still worth it at the same priority.
4. Treat "release notes mention a permission/isolation boundary fix" as a standing trigger for this same five-minute check going forward — the FO's own scan already does the reading; what was missing was someone actually running `claude --version` against it.

**Status: pitched.**

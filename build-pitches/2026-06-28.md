## PITCH: Encoded Guardrail Documents — Per-Role GUARDRAILS.md That Workers Self-Grade Against Before Calling Done

**Technique:** Each deployed role gets a lightweight `GUARDRAILS.md` in its context — a markdown table of behavioral invariants. Not task goals; hard behavioral constraints: "never include internal fleet state in a public audio script," "audio must pass QC ≥ 0.7 before render," "money-adjacent decisions stay on Claude, never route to free-tier or PAYG-keyless providers." The worker reads and self-grades against these before calling the task complete. When a failure breaks a guardrail, the post-mortem adds a new row — the lesson binds durably to the role rather than living only in a human's memory or a global `corrections.md` that the next instance may or may not load.

This is distinct from `/goal-bound` delegation: goal = "did I do the task?"; guardrails = "did I violate invariants the task description doesn't mention but must not?" A worker that completes every task step can still violate any of these. The guardrail is the missing check.

**Need it serves:**

Fleet pain: workers violate behavioral invariants that aren't part of the task description. Three documented live examples:

1. **Private-feed content in public podcast** (June 25): the build-pitch reporter loaded internal fleet state (STATUS files) that appeared in a public audio segment — not a task-goal failure, a behavioral invariant violation.
2. **Metered-key on money path**: during the credit crunch, alarm-responder routing hit the shared pool rather than the isolated money-monitor key — a behavioral invariant violation the triage code can't catch after the fact.
3. **QC-FAIL render**: episodes published before QC sign-off — the reason QC is "MANDATORY" in bold in CLAUDE.md, which workers may not load.

None of these are "I didn't finish the task." All three are "I finished the task while violating a behavioral constraint." The guardrail is the missing check.

Serves **Priority #2 directly**: workers that self-verify behavioral invariants before calling done are workers that don't surface violations to Kyle for cleanup — the definition of carrying work forward without his attention.

**Whole-fleet leverage:** Every dispatched role across ALL repos (podcast pipeline, alarm responder, COS/observer dispatch, fleet-optimizer) gets a self-verification layer for the "technically done but behaviorally wrong" failure class — at zero infra cost, zero credits per check, and the lesson accumulates durably in the role context without needing the next instance to re-derive it.

**Step 2 — Add self-grade step to the dispatch template (~30 min):**

In the worker briefing closing checklist (`~/.claude/skills/delegate/SKILL.md`), add:

```
BEFORE CALLING DONE:
1. Locate the GUARDRAILS.md for this role (brainrot-radio/GUARDRAILS.md, ~/.observer/alarms/GUARDRAILS.md, etc.).
2. Review each invariant row. If you violated any, fix it before filing the PR.
3. If a failure revealed a new class of violation not in the table, add a row with the invariant, rationale, and today's date.
4. Do not mark the task complete until you have passed all invariants in the table.
```

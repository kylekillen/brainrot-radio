## PITCH 1 (Primary): Agent Skills Progressive Disclosure — Restructure Context Docs Into a 3-Level Load Architecture

**Technique:** Claude Code's Agent Skills specification defines a three-level progressive disclosure architecture for contextual knowledge: Level 1 is YAML frontmatter metadata (~100 tokens per skill), always included in the system prompt regardless of task; Level 2 is the full `SKILL.md` body, loaded only when Claude determines this skill is relevant to the current task; Level 3 is bundled scripts and reference files, loaded only when actually referenced during execution. The result: you can install dozens of skills (context docs, editorial guides, domain expertise) without paying the context cost upfront. The system prompt stays lean; skills expand lazily when invoked. The distinction from slash commands is important — slash commands (`.claude/commands/`) are explicit workflow steps you trigger. Skills are contextual expertise that Claude loads proactively based on task relevance. Different tool, different job.

**Who's doing it:**
- **Anthropic engineers Barry Zhang & Mahesh Murag** — presented "Don't Build Agents, Build Skills Instead" at the AI Engineer World's Fair. Full talk at: https://www.youtube.com/watch?v=CEvIs9y1uog
  - Core framing: "We used to think agents in different domains would need their own scaffolding. What we realized is code is the universal interface — the agent is general; expertise is packaged as skills."
- **Anthropic official documentation** — explicitly describes the 3-level loading with token counts: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
- **Simon Willison** covered the launch in October 2025, calling it "maybe a bigger deal than MCP" and noting cross-platform adoption within weeks of the open standard release (December 18, 2025): OpenAI, Google, GitHub, and Cursor all adopted the Agent Skills standard. simonwillison.net
- **Corroborating analysis** — Swirl AI's breakdown "Agent Skills: Progressive Disclosure as a System Design Pattern" covers the architecture in depth and confirms the token-efficiency mechanism works as described.
- **Cole Medin** (another claude_lab channel) — his June 14, 2026 video "Google's Agents CLI: The CLI + Skills Combination to Ship AI Agents EASILY" (https://www.youtube.com/watch?v=1wfY7GCVvh0) demonstrates skills in practice: "One command installs the CLI and skills. Now with natural language we can ask our coding agent to build the agent, evaluate it, deploy it, harden it. Everything is packaged together. The CLI is the capability, the skills are the instructions."

**Evidence it's real:**
- Anthropic's own platform documentation describes the 3-level architecture with precise technical detail including token counts per level. Not a blog post — this is the implementation specification.
- The Agent Skills open standard launched December 18, 2025 and was independently adopted by competing platforms (OpenAI, Google, GitHub, Cursor) within weeks — cross-platform adoption is the clearest signal a standard is real.
- Simon Willison (highest-signal independent commentator on AI tools) published hands-on coverage describing the mechanism as "a clever approach to the context window problem." His commentary was unsponsored and skeptical-by-default; he called it a bigger deal than MCP, which is a strong statement from him.
- Kyle's own global Claude Code setup already uses skills (`/skill-creator` is in his installed skill list) — the mechanism is already running, just not applied to the brainrot-radio project.

**Why it matters for us:**
Yesterday's PITCH 1 (Cole Medin AI Layer, implemented June 13) restructured CLAUDE.md into lean globals + on-demand context docs in `.claude/context/`. That was the right structural move. Today's pitch is the upgrade: instead of manually loading context (someone has to know to pass the right context file to the right agent), Agent Skills make loading automatic and lazy.

The specific gap: Kyle's beat editorial guidelines (`.claude/context/beats/ai-tech.md`, `sports.md`, `agents-building.md`, etc.) currently have to be manually referenced. When the sports beat reporter runs, if it doesn't explicitly load `sports.md`, it runs without that guidance. An Agent Skill for each beat would instead surface automatically to Claude Code when it detects it's working on sports content — without any human wiring.

More concretely, the cost structure matters: if all seven beats' editorial guidelines were loaded at startup, that's thousands of tokens of context for every single session, including sessions where you're just running QC or publishing. As Agent Skills, each beat's metadata (~100 tokens each) is always present; the full 2000+ word editorial guide for that beat loads only when that beat is active. Seven beats × 100-token metadata = 700 tokens always-on vs. the full load cost only when needed.

The longer-term unlock: this is the architecture that enables the skill creator pattern. Claude can write and evolve its own skills during sessions (what it learned, what heuristics worked, new source patterns discovered) and those skills persist across sessions without manual CLAUDE.md editing.

**Build sketch** (an agent could run this cold from this file):
1. Audit the current `.claude/context/beats/` files and `.claude/commands/` files. Determine which are "workflow steps" (stay as commands) vs. "domain expertise that should load lazily" (convert to Skills).
2. For each beat editorial guideline (`ai-tech.md`, `sports.md`, `agents-building.md`, `claude-lab.md`, etc.) — restructure as an Agent Skill with YAML frontmatter: `name`, `description` (one line, triggers auto-loading), `version`. The body becomes the full editorial guideline. No other content changes needed.
3. Create a `.skills/` directory (or wherever the brainrot-radio project's Claude Code instance resolves skills — verify against `platform.claude.com/docs`) and place the restructured skill files there.
4. Install the `/skill-creator` skill in the brainrot-radio project context so Claude Code can generate new skills during episode generation sessions when it discovers recurring patterns.
5. Test: open a fresh Claude Code session and run `/generate-brief`. Check what the system prompt contains — does it include only skill metadata (compact summaries) rather than full editorial guidelines? If yes, the progressive disclosure is working.
6. Iterate: identify other context that currently loads globally but should load lazily (dedup rules, scoring algorithm, publishing config) and convert those as well.

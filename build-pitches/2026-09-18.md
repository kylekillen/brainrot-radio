## The pitch: a fleet-wide stand-down flag, enforced at the daemon layer, with a mandatory expiry + restore list
**Technique.** A single durable flag (file or DB row) that every Claude-spawning launchd daemon checks **before spawning a worker**, refusing to dispatch while set — enforced in the daemon's own wrapper/spawn path, not by relying on any role reading an INBOX or an agent choosing to honor a prompt instruction. The flag carries a scope (all / named daemons), an expiry timestamp, and a restore list (what was stopped, by whom, what should come back and when) — directly answering rule 2 of today's self-filed calibration entry.

**Who's doing it / corroborating sources.**
- [Multi-Agent Kill Switch: Why Stopping the Orchestrator Doesn't Stop the Swarm](https://dev.to/waxell/multi-agent-kill-switch-why-stopping-the-orchestrator-doesnt-stop-the-swarm-58aa) — the infra-layer-enforcement argument, pulled in full.
- [The Circuit Breaker Pattern for AI Agents](https://dev.to/brennhill/the-circuit-breaker-pattern-for-ai-agents-11pl) and [AI Agent Circuit Breakers: The Reliability Pattern Production Teams Are Missing](https://dev.to/waxell/ai-agent-circuit-breakers-the-reliability-pattern-production-teams-are-missing-5bpg) — converging, independently-authored detail on trip conditions and the "pause doesn't undo in-flight work" caveat.
- Real-incident corroboration cited across multiple of these (not fabricated by any one source): a $47K LangChain retry-loop bill over 11 days, a $30K agent-loop incident, and the 2012 Knight Capital $440M/45min algorithmic-trading runaway as the pre-LLM ancestor of the same failure shape.
- **Explicitly checked and rejected as evidence:** `KILLSWITCH.md` (0-star spec, not adopted — see above). Pushary's commercial "kill switch" product is real and shipping (verified pricing, app listings) but is a personal single-session pause tool via hooks, not a fleet/daemon-layer primitive — not the right shape for this gap, noted for completeness only.

**Evidence it's real.** Cross-checked past the search-snippet layer by fetching two of the strongest sources in full, verified the one dead standard's actual GitHub state via `gh api` rather than trusting the blog posts that cite it, and confirmed the underlying architectural claim (infra-layer enforcement, not in-agent cooperation) recurs across sources that don't cite each other. Most importantly: the need itself isn't inferred from any of this content — it's dated, self-filed, twice, by two different fleet roles, in the 24 hours before this scan, against a stated cost (three multi-day 100%-usage weeks).

## Need it serves
**Priority 3 — resilience, primary.** Directly closes the gap calibration.md names as the cause of "the pattern that's led to blackouts each week for months": no mechanism exists that can express "stop everything" to the layer that actually spends (launchd daemons), only to the layer that reads mail (roles).
**Priority 2 — secondary.** A fleet Kyle can't reliably stop with one directive is a fleet he can't safely hand ongoing work to without staying in the loop — the opposite of the multi-agent-without-Kyle unlock this priority is chasing.

## Whole-fleet leverage
One primitive, reused by every future stand-down (this is not the first one — it's the reason the last one had to be executed by hand at the launchd layer and still produced a false-crash misread the next day). Cheap to build (a flag file + one guard function + two call sites: `alarm-responder`, `task-dispatcher`), and the existing `pause_flag_active()` convention in `observer/coordination/__init__.py` gives it a pattern to extend rather than invent from scratch.

## Build sketch
1. Add a global flag surface, e.g. `~/.observer/pause-flags/FLEET-STANDDOWN.json`, holding `{scope, reason, set_by, set_at, expires_at, restore_list, lifted_by, lifted_at}` — the schema `calibration.md` says was missing today (rule 2).
2. Write one guard function (sibling to the existing `pause_flag_active(role.workspace)` in `observer/coordination/__init__.py`) that checks this file and returns refuse/allow, independent of any role/workspace.
3. Call that guard at the top of the spawn path in the two daemons named in yesterday's entry as the actual spend levers — `com.observer.alarm-responder` and `com.observer.task-dispatcher` — before they fork a `claude` worker. Log every refused spawn (count + timestamp) so "is it enforced?" is answerable by a number, not a `launchctl list` absence that looks identical to a crash.
4. Give Kyle a tap-only control per the global CLAUDE.md rule (he doesn't run CLI): a dashboard button for "Stand down the fleet" / "Resume," which writes/clears the flag file — mirrors the existing 09-17 fix pattern (`kyle_requested: true` gating in PR #839) that already solved an adjacent "prompt told it to, so it did" problem.
5. Mutant-test it the way PR #448/#873 were tested per this fleet's own discipline: set the flag, confirm zero new `claude -p` processes spawn from either daemon over a window; clear it, confirm normal drain resumes.
6. On expiry, auto-clear and log — so a forgotten stand-down doesn't itself become the next silent outage in the other direction.

## The find: `/skill-doctor` + the skill-listing budget (Claude Code v2.1.261, shipped 2026-09-04)

**Technique.** Every Claude Code session — interactive or headless — loads a
listing of every installed skill's name + description into its system prompt
on *every single turn*, regardless of whether that skill ever fires. That
listing has a hard budget (**1% of the model's context window** by default);
once the combined descriptions exceed it, Claude Code silently drops
descriptions starting with the **least-invoked skills first** — a brand-new
skill has zero invocations, so it is first in line to go mute: its name stays
in the list, its description vanishes, and the model has nothing left to match
your request against. `/skill-doctor` (new in v2.1.261) surfaces this directly:
it reports each loaded skill's context cost and invocation count so you can see
which skills are silently costing tokens on every turn while never being used
— and, separately, which ones may have already gone invisible to the router
without any error or notification.

**Who's doing it / corroboration.**
- Primary source, verified directly: Anthropic's own changelog —
  `raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`, the
  `## 2.1.261` section (published 2026-09-04T19:58:10Z per the GitHub Releases
  API — 3 days old): *"Added `/skill-doctor` to show which loaded skills go
  unused and what they cost in context, so you can prune them."*
- Official docs, fetched directly (`code.claude.com/docs/en/skills`): confirms
  the exact mechanism — *"The budget scales at 1% of the model's context
  window. When the listing overflows, Claude Code drops descriptions starting
  with the skills you invoke least, so the skills you use most keep their full
  text."* Also documents the three levers to fix it: `skillListingBudgetFraction`
  (raise the % of context reserved), `skillOverrides: "name-only"` (mute a
  specific low-value skill's description without deleting it), and
  `skillListingMaxDescChars`.
- Independent third-party corroboration, checked and consistent with each
  other and with the docs: Joe Njenga on Medium ("I Tried (New) Claude Code
  /skill-doctor (And Found Most Skills Are Dead Weight)"), Julian Goldie
  ("Claude Code Skill Doctor: Cut Wasted Context Fast" — confirms the
  v2.1.252+ rollout window and recommends re-auditing after every new plugin
  install), and a Substack piece specifically on scaling skill catalogs without
  burning context. None of these are the same source re-syndicated — three
  independent writers, same mechanism, same fix.

**Evidence it's real.** Not a demo or a hot take — it's a shipped, dated,
first-party CLI feature (verified against the raw changelog + GitHub Releases
API timestamp) with matching official documentation of the exact budget
mechanism, plus three independent practitioner write-ups converging on the
same description and the same fix. This clears the bar the other two
candidates in this week's scan didn't (the YouTube backlog was hype, not
technique).

**Need it serves.** Priority **(2) — the AI-businesses / multi-agent unlock,
and directly the "carries work forward without Kyle's constant attention"
goal.** Kyle's global skill catalog is **100 installed skills** (confirmed:
`~/.claude/skills` count), spanning marketing/SEO/ad-copy skills that have
nothing to do with most roles' actual work, alongside the fleet-specific ones
(`babysit`, `code-reviewer`, `delegate`, `log-finding`, etc.). Every one of the
18 standing roles in `roles.json` — COS, fleet-optimizer, finance-lead,
killen-time's own beat reporters, all of it — summons through `summon.py`,
which loads this same global catalog into every cold `build_seed()` on every
wake. That means (a) every headless wake is paying context tokens for dozens
of skills a given role will never invoke, and (b) any *newly added* fleet
skill (a fresh `code-reviewer`-style automation, say) risks being silently
muted by the invocation-frequency drop the moment the catalog grows past the
1% budget — with zero error, zero log line, just a name with no description
that the router can no longer match against. That is exactly the "reach"
failure class STATUS.md has flagged twice this month (2026-09-01, 2026-09-04:
"the channel that reaches carried the [wrong] version") — except this is the
same failure mode happening inside the harness's own skill-selection layer,
invisibly, on every single turn.

**Whole-fleet leverage.** One command (`/skill-doctor`, or its non-interactive
text-mode output for headless roles) run against 2-3 of the highest-skill-count
role workspaces tells us, in minutes, whether any of the fleet's own
mission-critical skills (not marketing skills) have already gone mute — and
costs nothing to check. If they have, the fix is a one-line settings change
(`skillListingBudgetFraction` or per-skill `skillOverrides`), not a build.
This is squarely a dev-loop/context-engineering win in the category this beat
is chartered to hunt (category d), and it's the kind of silent-failure class
the fleet has already spent real effort naming and fixing elsewhere
(`false_zero_controls`, the `handoff_guard`/reach failures above) — this is
one more instance of the same shape, caught early instead of discovered after
something breaks.

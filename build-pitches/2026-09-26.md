# Build-Pitch of the Day — 2026-09-26

## Weekly fleet friction miner: aggregate every session's tool errors deterministically, then turn the top recurring ones into hooks/rules

**What I read first (need-first).** `~/fleet-optimizer/STATUS.md` (through 09-23), `credit-resilience-plan.md`, `compound-loop-signals.md`, `dreaming-the-mechanism.md` / THREADS T22, and this beat's 09-19 → 09-25 pitches (sandboxes, auto mode, session resume, evals, drive-screen, stand-down flag, CI test-impact, advisor pilot, self-checkpointing, Opus 5.5 effort pin, early-stop guard, Jev/GLM watch items) so I would not re-pitch claimed ground. Live needs: (1) burn / cap pressure — Claude weekly at 100%, so every wasted turn costs scarce budget; (2) unattended agent work finishing without Kyle; (3) the fleet repeatedly rediscovering the same mechanical mistakes.

**Technique.** Your agent's own session logs (`~/.claude/projects/**/*.jsonl`) record every prompt, tool call and tool failure. Mine them in bulk, rank recurring failure patterns by frequency × workspace spread, and convert each into the smallest durable primitive that would have prevented it (a PreToolUse hook, a one-line rule, a skill). Cole Medin's framing: "fix the system, not the code," and "nothing to change here" is a valid answer, so one-offs don't become rules.

**Who's doing it.**
- Cole Medin, ["The Biggest AI Coding Agent Upgrade Is Already on Your Machine?!"](https://www.youtube.com/watch?v=td52e2tQFIU) (2026-09-25). Two versions: a one-prompt "opportunity-scan" skill, and a full version that loads conversations into database tables and queries them via MCP ("super token efficient"). He says he kept every change it proposed to his own AI layer. **Caveat: YouTube blocked the transcript (HTTP 429), so I worked from the full description and chapter list only, not the video itself.**
- The skill itself is public and I read it: [coleam00/skills → opportunity-scan](https://github.com/coleam00/skills/tree/main/.claude/skills/opportunity-scan). Reads a run's artifacts (reactive) or a window of weeks of session logs (proactive), aggregates rather than ingesting whole, and outputs the smallest rule/skill/hook/subagent/MCP change, ranked by impact × frequency.
- Anthropic ships the same idea natively at small scale: `/insights` is in the official command docs ([code.claude.com/docs/en/commands](https://code.claude.com/docs/en/commands): "HTML report analyzing your recent sessions on this machine … where things go wrong, and features to try"). Third-party write-ups describe it as looking at up to ~50 recent sessions and emitting CLAUDE.md additions ([Claude Lab guide](https://claudelab.net/en/articles/claude-code/claude-code-insights-command-guide), [DEV: CLI that turns /insights into skills/rules](https://dev.to/yahav10/i-built-a-cli-that-turns-claude-codes-insights-report-into-actionable-skills-rules-and-workflows-377)). The 50-session figure is third-party, not from the docs.
- Anthropic's Managed Agents "Dreaming" does batch transcript analysis with prevalence thresholds (already in our wiki, `dreaming-the-mechanism.md`), but its output is a memory store, not hooks/rules.

**Evidence it's real.**
- Three independent sources for the pattern (Cole's public skill, Anthropic's `/insights` doc row, Anthropic's Dreaming design), all built on transcripts already on disk. That's corroboration the *technique* exists and is used; it is **not** independent proof that acting on the output improves outcomes. Cole's "I kept every change" is a self-report.
- **I ran a spike on our own fleet (8 seconds, pure Python, zero model calls).** Last 7 days: 6,419 session files under `~/.claude/projects`; 1,377 (21%) contain at least one tool error; 3,793 tool errors total. The top *mechanical* (not test-failure) repeaters:

  | Error | Count | Sessions | Where |
  |---|---|---|---|
  | file exceeds max size, use offset/limit | 162 | 146 | model-router (45), fleet-optimizer (38) |
  | `read-only variable: status` (zsh) | 94 | 90 | spread across worktrees |
  | `No such tool available: bash` (lowercase tool name) | 86 | 85 | home dir, observer-system |
  | `File has not been read yet` before write | 88 | 80 | cos (24), model-router (9) |
  | `command not found: timeout` (macOS has no `timeout`) | 71 | 70 | spread (this run hit it too) |

  About 500 wasted turns in a week from five patterns that a two-line rule or hook each could remove. Each one is a mistake models keep making on this specific machine (zsh `status`, no GNU `timeout`), so per-workspace CLAUDE.md prose isn't reaching them.
- **Limits of my spike, stated plainly.** These are raw error counts, not verified cost; some "Exit code" errors are just failing tests and are legitimate. Wasted-turn cost per error is not measured. My regex for Kyle-style corrections ("no,", "stop", "I told you") found only 3 hits, because fleet sessions are mostly headless and machine-prompted, so this pitch does **not** claim to mine Kyle's corrections, only tool-level friction.

**Need it serves.** Burn/cap pressure and unattended reliability (priority 2: multi-agent work carrying forward without Kyle; indirectly priority 1, since fewer stalled or wasted agent turns means fewer interruptions). Not a trading change.

**What's new versus what we run.** `signals.py` friction signals are agent *self-reports* (1,330 in `~/.observer/signals`). Auto Dream (enabled 06-28) curates memory per workspace. `/insights` is per-machine, sampled, and interactive. Nothing today deterministically aggregates *all* ~6.4k weekly sessions' tool errors across workspaces and turns the top ones into hooks. The Fleet Optimizer has done this by hand (e.g. its "217 transcripts resolved" hook analysis) but only for one question at a time.

**Whole-fleet leverage.** One weekly zero-LLM script that ranks the fleet's recurring tool failures by session count and proposes a global hook/rule for each; ~500 wasted turns/week from five patterns alone, on a budget that is pinned at the cap.

**Build sketch.**
1. `observer-system/scripts/friction_miner.py`: walk `~/.claude/projects/*/*.jsonl` (mtime < 7 days), extract `tool_result` blocks with `is_error`, normalize (strip hashes, paths, numbers), count errors, distinct sessions and distinct workspaces per pattern. Skip anything that is test/lint output. My spike is ~35 lines: `/tmp/mine.py` pattern, reproducible from this description.
2. Emit a ranked table to `~/.observer/reads/YYYY-MM-DD-fleet-friction.md` (signed `<!--from: fleet-optimizer-->`), plus one `signals.py emit --category friction` per pattern above a threshold (≥20 sessions, ≥3 workspaces).
3. First fixes, all cheap: a PreToolUse hook (or global CLAUDE.md line) for `timeout` → `gtimeout` or a shell shim, a rule against assigning `status` in zsh, a rule to Read a file before Write/Edit and to use offset/limit on large files, and a note on exact-case tool names. Verify next week's counts drop, which makes this a real before/after measurement instead of a claim.
4. Optional second pass later: feed only the top-N patterns plus 3 exemplar excerpts each to a cheap model to draft the hook/rule text, human (or PR-reviewer loop) approves. Aggregation itself never needs a model.
5. Privacy: everything is local; no transcript content leaves the machine.

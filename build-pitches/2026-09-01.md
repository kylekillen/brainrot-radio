# Build-Pitch of the Day — 2026-09-01

## Hooks are the missing enforcement layer: rules only guide, hooks guarantee — and the fleet's dominant recurring bug class is rules that were written down but never bound to the path that runs

**Technique.** Claude Code (and every other major coding-agent harness) draws
a hard line between two different mechanisms that look similar in a CLAUDE.md
but behave completely differently at runtime: **rules/CLAUDE.md are advisory**
— the model reads them as context and usually, not always, follows them —
while **hooks are deterministic shell commands the harness runs itself** at
defined lifecycle points (`PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`,
etc.), independent of whether the model remembers or chooses to comply. A
`PreToolUse` hook can outright deny a tool call (exit code 2 / explicit
`permissionDecision: deny`); a `Stop` hook can refuse to let a turn end until
a condition is met; a `SessionStart` hook can force specific context into
every fresh session, including after compaction. The actionable part is an
**audit method**: for every line in a rules file, ask "does this name an event
— *when X happens, do Y* — or does it encode judgment?" Event-shaped rules
should become hooks; judgment-shaped rules stay as prose; anything that's
neither (restating what the model already knows) should be deleted.

**Who's doing it.** Cole Medin, "Watch This If Your Coding Agent is Ignoring
Your Rules (You Need Hooks)" — https://www.youtube.com/watch?v=msfMqW92Y8Q
(published 2026-08-27, claude_lab feed). Walks through this exact audit method
against his own global rules file and converts several of them into hooks live
(a `.env`-read block, a "read coupled files before editing" gate, a
"run full test suite before the turn can end" stop-hook).

**Evidence it's real — independently cross-checked, not just this one video.**
- **Anthropic's own first-party docs say the identical thing in the identical
  words.** `code.claude.com/docs/en/hooks-guide`: "Hooks are user-defined
  shell commands... which gives you deterministic control: certain actions
  always happen rather than relying on the LLM to choose to run them," versus
  CLAUDE.md/rules being advisory context. The event taxonomy Cole Medin
  demoed (`PreToolUse` can block, `PostToolUse` for logging/observability,
  `Stop` for turn-completion gating, `SessionStart` for context re-injection
  after compaction, with a `source` field distinguishing `startup` /`resume`/
  `compact`/`clear`) matches the official reference exactly.
- **Independent practitioner convergence, not just this channel:** Blake
  Crosley, "Claude Code Hooks Explained: The Deterministic Layer Around Your
  Agent" and "Why Each of My 95 Hooks Exists" (blakecrosley.com); claudefa.st,
  "Claude Code Hooks: Complete Guide to All 30 Lifecycle Events"; a Substack
  piece titled "Claude Code hooks explained: the missing layer between prompts
  and production." All independently land on the same rules-vs-hooks framing
  and the same "hooks are for things that must happen every time, without
  relying on the model to remember" thesis.
- **Structural corroboration from Anthropic's own July 2026 change:**
  Anthropic cut Claude Code's system prompt by over 80% (800→164 tokens,
  confirmed via multiple independent outlets — Techstrong.ai, AI Weekly,
  Developers Digest, ClaudeAINews, Mike Gingerich), explicitly because bloated
  advisory rules were splitting the model's attention and sometimes hurting
  judgment calls. This is the same underlying claim from the opposite
  direction: don't cram process into prose rules — Anthropic pulled process
  *out* of the system prompt as they built more of it into progressive
  disclosure and tools. (Caveat: the specific "self-evolving-rules-vs-hooks"
  benchmark study Cole Medin cites on screen, I could not independently
  locate/verify — treat that one number as unconfirmed. The rules-vs-hooks
  mechanism itself is confirmed via Anthropic's own docs, independently of
  that study.)

**Need it serves.** This is not a speculative technique — it names the fleet's
own most-repeated, most-expensive failure pattern, already logged multiple
times in `~/fleet-optimizer/STATUS.md` as a "generalizable" lesson, each time
discovered and patched separately instead of as one class:
- `burn_budget.json`'s pause flag: the config's own note says truthfully
  "both its launchd scripts check this flag" — and that's exactly why it read
  as covered. The actual money-spending path, the mail-triggered headless
  summon (`observer_role_monitor.py`, `wake_role.py`, `observer_tickler.py`),
  contains the word `pause` **zero times**. fleet-optimizer was summoned past
  its own active pause flag three times in eight hours while 1.9x over its
  weekly cap (STATUS 2026-08-29 08:55). This is a rule that was documented as
  a guarantee but was, in fact, advisory — the textbook case a `PreToolUse`
  or dispatch-time hook exists to close.
- The Identity-layer GitHub-link bullet that "kept reverting" for months
  despite repeated per-session corrections (per CLAUDE.md's own changelog) —
  a rule fighting to be a guarantee, patched by rewriting prose harder instead
  of enforcing it structurally.
- The "already-answered ledger" re-ask bug (STATUS 2026-09-01 00:1x, shipped
  as PR #572, `scripts/kyle_rulings.py`) — the fix that shipped **is itself a
  SessionStart hook pattern**, built ad hoc for one incident. It generalizes.

This moves priority **(2) — the multi-agent unlock** — directly: a fleet of
delegated AIs "carrying work forward without Kyle's constant attention" only
works if standing decisions and guardrails actually bind on every path an
agent can take, not just the ones someone remembered to wire a check into.
It also reduces priority (1) drag, since every one of these misses eventually
surfaces as a "Kyle, please re-rule on X" interruption.

**Whole-fleet leverage.** One audit-and-hookify pass, run once against the
fleet's standing rule surfaces (global CLAUDE.md, `burn_budget.json`'s
documented guards, `decision-protocol.md`), converts a class of bugs that has
so far been discovered and patched incident-by-incident (at least 3 separate
STATUS.md entries in the last week alone) into a single deterministic
enforcement mechanism applied at every role's session boundary and every
tool call — not a per-repo or per-incident fix.

**Build sketch.**
1. Apply Cole Medin's audit test to the fleet's standing rule/config surfaces:
   for each line, is it "when X happens, do Y" (→ hook) or judgment (→ stays
   prose) or neither (→ delete)? Start with `burn_budget.json`'s `_why` notes
   and `~/observer-system/CLAUDE.md`.
2. **Highest-value first hook:** a dispatch-time gate in the headless-summon
   path (`observer_role_monitor.py` / `wake_role.py` / `observer_tickler.py`)
   that reads the relevant role's pause flag in `burn_budget.json` before
   spawning any Opus summon — closing the exact hole STATUS.md measured, with
   a positive control (deliberately trip a pause flag, confirm the next
   summon attempt is blocked) rather than trusting the fix by inspection.
3. **Second candidate:** generalize PR #572's `kyle_rulings.py` into the
   fleet's standard `SessionStart` pattern — any standing ruling gets injected
   into every role's context at session start by default, not special-cased
   per incident after it's already caused a re-ask.
4. Use Claude Code's documented hooks schema (`code.claude.com/docs/en/hooks-guide`)
   directly, or Cole Medin's referenced `/hooks create` skill pattern, to
   scaffold and wire hooks into each role's `.claude/settings.json`.

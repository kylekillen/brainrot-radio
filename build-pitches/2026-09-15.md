## The find: `drive-screen` — a safety-audited, dependency-free screen-control skill, and its own written safety rules independently rediscover a lesson the fleet paid for in a real incident
**Technique.** `drive-screen` is a Claude Code / coding-agent skill (not a
platform feature, not a paid tool) that gives an agent real desktop control —
list/focus windows, type, paste, click, scroll, screenshot, and watch or steer
*another* coding-agent session running in a terminal — using only native OS
scripting (AppleScript on macOS, PowerShell on Windows, comparable tools on
Linux). No computer-use API, no VM, no extra install: just the skill file plus
three Python scripts (`screenctl.py`, `session_watch.py`, `autodrive.py`) that
the agent calls as a CLI. Its own description states plainly it is **"not for
browser automation, which has its own headless tooling"** — this is for GUI
apps and desktop-level tasks with no CLI/API surface, not a replacement for the
fleet's CDP portal-login path.

**Who's doing it.** Cole Medin, video published 2026-09-15:
[youtube.com/watch?v=SWEThyRHMgQ](https://www.youtube.com/watch?v=SWEThyRHMgQ).
Source code: [github.com/coleam00/skills](https://github.com/coleam00/skills),
path `.claude/skills/drive-screen/SKILL.md` + `scripts/`.

**Evidence it's real — verified against the artifact itself, not just the video's word.**
I did not stop at the video's claims; I pulled the actual skill source via
`gh api` and read it directly:
- Repo is real and active: **534 stars, MIT license**, and `pushed_at` /
  `updated_at` both show **2026-09-15** — pushed *today*, actively maintained,
  not an abandoned demo repo.
- The skill file is **361 lines** (matches the video's "a little under 400"
  claim) and ships with real test files (`_test_screenctl.py`,
  `_test_autodrive.py`) alongside the three CLI scripts — not vaporware.
- Its own written "hard rules" are specific and falsifiable, not marketing:
  explicit human handover required every time (no standing consent), re-verify
  window focus by identity before every keystroke (exit 1 on mismatch, "the
  single most common failure, and the damage is done before it is visible"),
  treat on-screen content as untrusted input (cites a published PoC where
  screen text drove a computer-use agent to attempt a filesystem wipe), never
  close or restart a window the agent didn't open, and — the standout one —
  **"Read results from the transcript or the log, not from pixels... never
  report a result you did not read from a file."**
- **That last rule is independent, convergent corroboration of a lesson this
  fleet already paid for.** `~/fleet-optimizer/STATUS.md`, 2026-09-07 21:35:
  *"Never infer session state from what the screen shows; ask `/dev/console`
  who owns it"* — from an incident where a lock screen and a login window
  looked visually identical but meant opposite things. A different author, a
  different month, a different codebase, landing on the identical operational
  rule. That's a stronger signal than a demo: it means the rule generalizes,
  not that one video said so.
- Corroboration beyond the primary source: [Stork.AI's
  write-up](https://www.stork.ai/blog/this-ai-skill-replaces-bloated-agents)
  independently describes the same mechanism (AppleScript/PowerShell, no extra
  install, ~400 lines) and flags the same caveat — "best used for trusted,
  routine tasks rather than high-stakes production automation" — though it
  adds no verification beyond restating the creator's claims, so I'm weighting
  the source-code read above it, not this write-up.

## Need it serves
**Priority 2 — the multi-agent-without-Kyle unlock, primary.** The fleet has
wanted GUI-level automation for over a month (Hammerspoon + `cliclick` staged
on the laptop since at least early August per the 08-09/08-10/08-11 digests)

headless `claude --print` can't reach — and as of 2026-09-07,

entitlement, a one-tap Kyle fix nobody has flipped. When that toggle finally
gets flipped, the fleet currently has no *disciplined* tool waiting — just a
raw accessibility API and whatever ad hoc script gets written under time
pressure. `drive-screen` is a battle-tested, safety-ruled tool ready the
moment that gap closes, for the exact use case Kyle already asked about once
(driving the laptop's screen).
**Priority 3 — resilience, secondary.** Its `session_watch.py`/`autodrive.py`
pair — watching a driven coding-agent terminal session and auto-answering
routine permission prompts while stopping on anything genuinely ambiguous — is
a concrete, working instance of exactly the judgment call the fleet keeps
getting wrong in the other direction: `calibration.md`'s freshest entry (cited
in the 09-11 pitch) is a role escalating to a human on the untested theory that
something needed one, costing a 9-hour stall. This skill's own "hard rules"
name the same distinction explicitly (confirm before anything destructive or
outward-facing; never auto-approve a prompt you haven't read) — a worked
example of where that line sits, not a new invention.

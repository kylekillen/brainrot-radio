# Build-Pitch of the Day — 2026-08-30

## Pitch: Turn the fleet's "always check the flag" rules into hooks — deterministic gates instead of remembered conventions

**Technique.** Claude Code (and other harnesses) support `hooks`: shell/script callbacks the harness itself fires at fixed lifecycle points (`SessionStart`, `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop`), independent of the model's sampling. Unlike a CLAUDE.md rule or a written policy — which the model *usually* follows — a hook's exit code can hard-block an action (exit 2 = "you may not do this / you may not stop yet") or force the agent to act. The framing that makes this a system-design point, not a trivia fact: a rule is a request; a hook is a guarantee. The corollary technique is a simple audit heuristic — for each line in your rules/CLAUDE.md, ask "is this naming an event (`when X happens, do Y`) or encoding judgment (`prefer X style`)?" Event-shaped rules should become hooks; judgment-shaped rules should stay rules; anything that's neither should be deleted.

**Who's doing it.**
- [Watch This If Your Coding Agent is Ignoring Your Rules (You Need Hooks)](https://www.youtube.com/watch?v=msfMqW92Y8Q) — Cole Medin, published 2026-08-27. Full walkthrough of the rules-vs-hooks distinction, a `PreToolUse` block on reading `.env`, a `Stop` hook that force-reruns the test suite until green, and the audit heuristic above. Cites a controlled study showing an agent that's allowed to keep appending to its own system prompt/rules gets *worse* on every task type, while adding hooks ("middleware") helps on every task type except the hardest.
- Corroboration that this is real consensus, not one YouTuber's opinion: Anthropic's own July 2026 write-up on Claude Code's context engineering (["The new rules of context engineering for Claude 5 generation models"](https://www.anthropic.com), widely covered — [Techstrong.ai](https://techstrong.ai/agentic-ai/anthropic-cut-80-of-claude-codes-system-prompt-heres-why-that-matters-for-your-agents/), [the-decoder.com](https://the-decoder.com/anthropic-says-it-cut-80-percent-of-claude-codes-system-prompt-because-fable-5-models-want-a-smaller-system-prompt/)) independently states "rules become judgment" as one of six shifts, and that Anthropic cut 80%+ of Claude Code's own system prompt with no eval regression by moving enforcement out of prose. Independent technical explainers on the deterministic-vs-probabilistic framing: [Claude Code hooks docs](https://code.claude.com/docs/en/hooks-guide), [Ranjan Kumar — "Hooks: The Enforcement Layer That Turns Agent Policy Into Agent Fact"](https://ranjankumar.in/hooks-policy-as-code-agent-enforcement), [ranthebuilder.cloud — "Agentic Coding Hooks: Deterministic AI Guardrails"](https://ranthebuilder.cloud/blog/agentic-coding-hooks-deterministic-ai-guardrails/). All converge on the same recommendation: reserve hooks for the small set of rules that must hold *every* time (destructive actions, secrets, the one or two invariants that actually matter) — not everything.

**Evidence it's real.** Cross-checked against Anthropic's own published guidance (not just a channel demo), two independent technical write-ups reaching the same deterministic/probabilistic framing, and the official Claude Code hooks docs describing the exact mechanism (PreToolUse/Stop/exit-code semantics) shown in the video. Not vaporware — hooks are a shipped, documented Claude Code feature; the pitch is the *pattern of use* (convert process-shaped rules to hooks), not a new tool to install.

**Need it serves.** The fleet's own STATUS.md from the last 24h shows this exact gap, twice, in the highest-stakes places:
1. **Burn-pause enforcement is a convention, not a guarantee.** 2026-08-29 08:55: the fleet-optimizer's burn-pause flag is honored by two launchd scripts that were told to check it, but `observer_role_monitor.py`, `wake_role.py`, and `observer_tickler.py` — the mail-triggered reactive summon path — contain the word "pause" zero times. The role was summoned three times past its own cap in eight hours. This is precisely "a rule that should be a hook": *when a session is about to start, check the pause flag* is an event, not a judgment call, and it was relying on every entry point remembering to check it independently.
2. **"Zero problems" reports with no proof the check could ever have found a problem.** 2026-08-29 09:55: four unrelated instruments across four desks all failed toward "everything is fine" in the same hour (a deleted test counter reading `0==0`, a `grep` on a missing file, a config field silent about a third path, an alarm-responder misreading a crash as an empty field) — 867 of 893 false verdicts in one storm. A `Stop`/`PostToolUse` hook that requires any "0 findings" report to cite an independent positive-control result before being accepted would catch this class deterministically, the same way the video's stop-hook forces a red test suite to actually get fixed instead of being narrated as "done."
This directly serves priority (2) — the multi-agent unlock is work that "carries forward without Kyle's constant attention," which requires the fleet's own safety rules to actually hold when no one is reading the transcript. Right now they're prose, and prose is exactly what's been failing.

**Whole-fleet leverage.** Every role in the fleet already runs Claude Code and already has a `.claude/settings.json` (confirmed: the global config already uses `Stop` hooks for auto-commit/notify side-effects) — this is a zero-new-infrastructure change, just adding `PreToolUse`/`SessionStart` *gating* hooks where the fleet currently only uses hooks for *observation* (commits, Slack mirror, voice). Cross-cutting: fixes a class of failure (rule ≠ enforcement), not one incident.

**Build sketch.**
1. Confirm the gap: `grep -c pause observer_role_monitor.py wake_role.py observer_tickler.py` (STATUS already reports this as zero — verify still true before building).
2. Add a single shared gate function (e.g. `observer-system/scripts/burn_gate.py`) that all three summon entry points call before spawning a Claude session — read the pause flag, exit non-zero / raise if paused. This is the "extract the event out of the rule" move: one deterministic checkpoint instead of three places asked to remember.
3. Run the audit heuristic from the video against `~/.observer/wiki/calibration.md` and the global `CLAUDE.md`: for each line, is it naming an event or encoding judgment? Pull the event-shaped ones (there are likely more beyond burn-pause — e.g. "always fail loudly," "commit and push completed work" are arguably Stop-hook candidates already partially covered) into hook candidates.
4. For the "zero-findings" failure class: add a `Stop` hook template for any role that runs audits/sweeps (fleet-optimizer, pr-review-sweeper) requiring a logged positive-control result alongside any "0 found" conclusion before the finding is accepted as final.
5. Use Cole Medin's `/hooks-create`-style interview pattern (describe the guarantee in plain language, let an agent build + wire the hook) rather than hand-writing settings.json — lowers the cost of doing this repeatedly across roles.

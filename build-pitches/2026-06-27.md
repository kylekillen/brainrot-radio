## PITCH: The Planning Meta-Skill — Separate Dispatch Brief Generation Into Its Own Session to Eliminate Context Rot and Worker Re-asks

**Technique:** Before the COS dispatches a worker, run a dedicated planning session (fresh context, separate from the COS session) that generates a structured spec document as the worker's brief. The planning session reads relevant wiki pages, STATUS files, and context docs, then fills a structured template with: Q&A blocks answered from existing context (not by Kyle), per-phase task breakdown, new-vs-existing file declaration, and runnable validation commands. The worker receives the structured spec — not a COS-written prose brief — and starts with everything it needs to finish without interrupting Kyle.

Two key mechanisms: (1) **separate session** prevents the planning agent's accumulated context from contaminating the worker's fresh start (Google's "context rot" failure mode); (2) **structured template** makes the brief a machine-readable, self-contained artifact rather than a free-form paragraph (IndyDevDan's proven meta-skill pattern).

**Build sketch** (agent-executable, additive):

**Step 1 — Create the spec template: `~/.claude/skills/spec-brief.md`** (~30 min)

```markdown
# Dispatch Spec Template

## Task
<One-sentence summary of what this worker should build or fix>

## Context — back-references (COS fills from wiki/STATUS before dispatch)
- Relevant wiki pages: [ list ]
- Related PRs or past work: [ list ]
- Constraints or known blockers: [ list ]

## Q&A — resolved before dispatch (COS answers from context, not Kyle)
- Q: <anticipated ambiguity 1>
  A: <answer from wiki/STATUS/code>
- Q: <anticipated ambiguity 2>
  A: <answer>

## Phase Breakdown
Phase 1 — [ name ]: [ what to do ]
Phase 2 — [ name ]: [ what to do ]
...

## New vs. Existing Files
- CREATE: [ files to create ]
- MODIFY: [ files to change ]
- DO NOT TOUCH: [ files out of scope ]

## Validation Commands (worker runs these to self-check)
```bash
# Run these before filing the PR
<test command>
<lint command>
<integration check>
```

## Completion Criteria
The task is done when: [ specific, verifiable criteria ]
```

**Step 2 — Add planning pass to the delegate skill** (~45 min):

In `~/.claude/skills/delegate/SKILL.md`, before generating the worker brief, add a planning phase:

```
PLANNING PHASE (runs in the current session before dispatch):
1. Read the task description.
2. Load relevant context: check ~/.observer/wiki/ for related pages; check STATUS files for open items; read any referenced code files.
3. Fill out the spec-brief.md template sections — resolve Q&A from context (don't ask Kyle unless there's no answer anywhere).
4. Save the filled spec to a temp file: .tmp/dispatch-spec-YYYY-MM-DD-HH.md
5. Dispatch the worker with the spec file as its primary briefing document.
```

**Step 3 — Optional Fable 5 enhancement** (zero new infra):

For high-stakes dispatches, run the planning phase under `--model claude-fable-5` (the planning-quality benefit justifies the credit spend for complex tasks; use Opus 4.8 default for routine ones).

## Pitch 1 — Pilot the `--advisor` (Opus-advises-Sonnet) pattern on the dispatcher lane, and use it to measure whether the "Sonnet vs Opus" fight can be dissolved

**Technique.** Claude Code 2.1.260+ can pair a cheaper main model with a stronger *advisor*: the main model (say Sonnet 5) does the work and, at decision points — before committing to an approach, on a recurring error, before declaring done — consults Opus 5, which reads the whole transcript, returns guidance, and never calls tools or writes output. It is one flag (`claude -p --advisor claude-opus-5`, hidden from `--help`), one setting (`advisorModel`), or `/advisor` in any session including `-p` and the Agent SDK; subagents inherit it. Runs server-side, available on subscription and API accounts, advisor tokens count against plan limits.

**Who's doing it.**
- Anthropic, "The advisor strategy: Give Sonnet an intelligence boost with Opus": https://claude.com/blog/the-advisor-strategy — Sonnet + Opus advisor +2.7 points on SWE-bench Multilingual at −11.9% cost per task vs Sonnet alone (measured with Sonnet 4.6 / Opus 4.6); Haiku + Opus advisor 41.2% vs 19.7% on BrowseComp.
- Claude Code docs, "Escalate hard decisions with the advisor tool": https://code.claude.com/docs/en/advisor — flag/setting/command, pairing table, headless support, billing, prompt-cache behaviour.
- Claude API docs: https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool and https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence (the honest measurement page — see below).
- Third-party writeups (builder.io https://www.builder.io/blog/the-claude-advisor-pattern, MindStudio, Botoi and others) exist but **only restate Anthropic's numbers**; builder.io says so itself: "All of these benchmarks are Anthropic's own. No independent third-party results exist yet."

**Evidence it's real — and how far it goes.** Verified: the mechanism exists, is documented in three official places, and works on this machine. I ran it (~$0.68 total, deliberately tiny):
`echo "<prompt>" | claude -p --model claude-sonnet-5 --advisor claude-opus-5 --output-format json --max-budget-usd 0.50 --tools ""`
The JSON `modelUsage` showed both models billed separately — sonnet-5 $0.29 and **opus-5 $0.385 (70.6k input, 1.3k output)** — i.e. the flag is accepted headless, the advisor was consulted on request, and it works under our current auth. Two things fell out that are not in the marketing:
1. **A single consult on a trivial one-sentence question was 57% of the call's cost**, because the advisor re-reads the entire transcript uncached (docs: "each advisor call processes the full transcript anew, with no reuse between calls"). Advisor economics only work when consults are few and the executor's own loop is long.
2. **The advisor's spend counted against `--max-budget-usd` and cut the run off** (`error_max_budget_usd`, empty result) — the fleet's per-summon ropes ($3 maintenance, $20 lead) will need to be re-sized before advisor turns are enabled, or a rope tuned for Sonnet will truncate mid-task.

Not verified, and Anthropic's own docs say so plainly: that it saves money *on our model pair*. The 11.9% figure is Sonnet 4.6/Opus 4.6. For the current Sonnet 5 + Opus 5 pair the docs rate the gain "few points" with "medium-low" consult rate, warn that consult rate is fragile (on one benchmark a Sonnet 5 executor gained 23 points because it kept consulting; on another it stopped consulting and gained nothing), and say that if the executor consults on most tasks you should just run the advisor model alone at low effort. The only independent evidence is my one spike. **This is a measured-pilot pitch, not a "turn it on fleet-wide" pitch.**

**Need it serves.** Burn (fleet-wide, priority 3 resilience + priority 2 multi-agent throughput). It is the only mechanism I found that could resolve the Sonnet-vs-Opus ruling conflict by *not* being a per-role or per-cause binary: Sonnet does the mechanical turns, Opus is consulted at the plan and before "done". It also happens to target a documented failure shape — the 09-19 fleet-optimizer entry ("prior HANDOFF claimed the job was armed; it wasn't — state claims need verification") is exactly an executor declaring done without an independent check, and "before declaring a task complete" is one of the three moments the advisor is designed to fire on.

**Whole-fleet leverage.** If it works on our pair, it lowers Opus's share of the burn without the "capability regression" Kyle vetoed for leads; if it doesn't, one week of data closes the question with evidence instead of another ruling.

**Build sketch (an agent can do it; Kyle has no step).**
1. **Baseline first, per the docs' own rule.** Price the same task set on Sonnet 5 alone, Opus 5 alone at `low` effort, and Sonnet 5 + Opus 5 advisor. The pairing must beat Opus-alone-at-low, not just Sonnet-alone. Reuse `~/model-router` Killen Bench task classes if the cases fit; otherwise replay ~20 recent closed dispatcher tasks.
2. **Pilot lane: the task dispatcher** (`observer-system/scripts/run_task.sh`, default model `sonnet`, worker output lands as PRs the code-reviewer loop already grades). Add `--advisor claude-opus-5` behind an env var (e.g. `OBSERVER_TASK_ADVISOR`, default off) on a sampled fraction of tasks. Metrics already exist: cost per task (`--output-format json` gives per-model `costUSD`), reviewer verdict, changes-requested rounds, CI-red rate. Do NOT touch the lead/Kyle-caused summon path (`HEADLESS_SUMMON_MODEL`) in the pilot — that path has Kyle's explicit capability ruling.
3. **Instrument consult rate**: count `advisor_tool_result` blocks per run from the stream-json/transcript. If consults/task is ~0 or >3 the pairing is failing by the docs' own criteria; add the docs' suggested "consult once before substantive work and once before finishing" system-prompt block for coding tasks and re-measure.
4. **Re-size ropes** for advisor-enabled runs (advisor spend counts against `--max-budget-usd`; see finding 2).
5. **Decision after ~1 week / N tasks:** report cost-per-merged-PR and reviewer-bounce rate for the three arms. Only if the pairing wins on both, take it to Kyle as a proposal for the *lead* class (his call, since it touches his ruling), starting with a single role.
6. Env gotchas: advisor is off if flag-fetching is disabled (`DISABLE_TELEMETRY` etc. — not set on this machine, checked); Anthropic API only (fine here, breaks on Bedrock/Vertex or a gateway that doesn't forward server tools — relevant if `~/model-router` ever proxies Claude calls); Sonnet 5 accepts Opus 4.7+ / Fable / Sonnet 5 as advisors, Opus 4.6 fails with an API error.

**Honest limits.** Vendor-only evidence; no third-party replication; my spike is n=1 on a trivial prompt and mainly proves cost mechanics, not quality. Fleet burn is currently low because of the 09-17 stand-down, so this is for when load returns, not an emergency. A Fable advisor would bill to usage credits on some plans (not needed for the Opus pilot).

## Pitch — `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`: a harness-enforced subagent-model ceiling that closes the exact cost leak the fleet already found in its own routing

**Technique.** Claude Code v2.1.257 (shipped 2026-09-01) added
`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, which makes `CLAUDE_CODE_SUBAGENT_MODEL` (or the main
session's model) apply to **every** subagent a session spawns, ignoring that subagent's own
`model:` frontmatter and any explicit per-spawn model override. This closes a gap Anthropic
itself opened one release earlier: v2.1.251 (Aug 28) changed `CLAUDE_CODE_SUBAGENT_MODEL`
from an override to a mere *default*, explicitly letting an agent-definition's `model:` and
a per-spawn model win over it. `_FORCE` is the escape hatch back to a real ceiling, for
exactly the case where you want one dial that no individual agent definition can override —
their own changelog language: "for example to pin an entire evaluation run to one model."

**Who's doing it.** Anthropic itself, first-party. Verified directly against the primary
source, not a paraphrase: `raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`,
line 192 (`## 2.1.257` section) for the `_FORCE` addition, and line 360 (`## 2.1.251` section)
for the change it patches over — read both in full, not summarized secondhand. A prior
AI-summarized fetch of the hosted changelog page initially mis-attributed this to a different
version; re-verifying against the raw file was necessary and is the reason this pitch names
exact line numbers rather than trusting the summary.

**Evidence it's real.** Directly read primary source (raw CHANGELOG.md from the
`anthropics/claude-code` GitHub repo — the same repo, not a mirror or blog). This is a shipped,
dated, first-party harness feature, not a demo, technique write-up, or third-party claim.

**Need it serves.** Priority **(2)/(3) — cost resilience of the multi-agent unlock.**
STATUS.md 2026-08-29 already measured Opus 5 at **76% of the fleet's month-to-date spend
($4,799 of $6,306), all of it in the summon layer**, and separately found **13 dashboard
threads carrying `default_model: claude-fable-5`** as leaked per-thread picker state, plus
Kyle's global `~/.claude/settings.json` still pinning `model: fable` — both cases of a cost
policy living as a convention (an agent-definition frontmatter field, a picker's remembered
state) rather than a guarantee. That finding is the same "rule vs. hook" gap the fleet has
already generalized from three separate hooks pitches this week (08-30, 08-31, 09-01) — this
is that exact pattern, but for the specific mechanism (subagent spawn) driving the specific
number (76% of spend) the fleet already flagged as its worst cost offender.

**Whole-fleet leverage.** One environment variable, set once at the launcher level, becomes
a harness-enforced ceiling on every subagent any role fans out — this podcast's beat
reporters, fleet-optimizer's investigation agents, the COS's worker dispatch — regardless of
what any individual agent definition or per-spawn call requests. Zero new infrastructure;
it's a config change, not a build.

**Build sketch.**
1. Set `CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5` (or whatever the cause-keyed routing
   policy names for self-directed/maintenance work) and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`
   in the launcher environment for roles whose summon-layer spend is the concern (fleet-
   optimizer, the COS's dispatcher, this podcast's beat-reporter fan-out) — start with
   whichever role's `/usage` breakdown shows the highest subagent-spawn share.
2. Verify it actually overrides the killen-time masthead's `claude-fable-5` agent-definition
   pins and the 13 leaked `default_model` dashboard threads named in the 08-29 STATUS.md
   entry — those are precisely the per-definition/per-thread overrides this flag is built to
   beat, so they're the right test case before rolling it out fleet-wide.
3. Confirm this doesn't fight the RIGOR TIER: money/trading roles must stay pinned to their
   own high-capability floor regardless of this ceiling — scope the env var per-role
   (launcher-level, not a single fleet-wide value), not as one setting for every role.

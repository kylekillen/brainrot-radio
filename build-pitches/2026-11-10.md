## Pitch 2 (carried forward, sharpened): Adopt a typed context graph via MCP — retrieval layer complement to the Fable lead agent.

**Technique.** Agents fail not because context windows are too small but because they lack a knowledge graph of the code, APIs and runtime they operate on, and then guess.

**Who's doing it.** Cole Medin — "Your Coding Agent Knows Your Code, But Not Your Actual App (Here's the Fix)" (https://www.youtube.com/shorts/EMIRXv2iE_Q, 2026-11-06); OutSystems MCP; Postman context graphs (https://blog.postman.com/why-ai-coding-agents-need-context-graphs/).

**Evidence it's real.** Context-rot research (Chroma 2025; Stanford "lost in the middle") shows longer prompts stop helping before windows fill; Postman's context graph measurably helped (GPT 6.1 Terra: 42% faster, 43% fewer tokens).

**Need it serves.** Priority 2 primarily (autonomous loops that can actually carry work forward), priority 1 secondarily.

**Delta vs Kyle's current setup.** Already pitched 2026-11-09 and filed to the deferred queue. Today's delta is sharpened by Fable 5.2: with a real lead agent able to question inherited conclusions, the retrieval gap becomes the binding constraint — the graph becomes load-bearing rather than nice-to-have.

**Whole-fleet leverage.** One adopt per agent loop.

**Build sketch.** (unchanged from 2026-11-09; revisit condition now: a traced incident of an agent failing for want of code→runtime context.)

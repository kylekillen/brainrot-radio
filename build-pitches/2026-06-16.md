## PITCH 1 (Primary): Model-Tier Routing via `Tool(param:value)` Permission Rules

**Technique:** Claude Code v2.1.178 (released June 15, 2026) adds a `Tool(param:value)` syntax to permission rules that lets you match not just *which* tool is invoked but *what value was passed to a specific parameter* — with wildcard support. The headline example from the changelog: `Agent(model:opus)` as a deny rule blocks any Opus-tier subagent spawns. Combined with independent benchmark evidence that Sonnet performs within 85–90% of Opus on 80% of tasks (and Opus within 5–10% of Fable on most), this is the primitive needed to build a cost-optimal model-routing layer for a multi-step agent pipeline: deny expensive tiers where they're not earning their price, allow them only in the steps that genuinely require them.

**Who's doing it:**

- **Claude Code official changelog v2.1.178** (June 15, 2026): https://github.com/anthropics/claude-code/releases/tag/v2.1.178 — "Added Tool(param:value) syntax for permission rules to match a tool's input parameters (with * wildcard), e.g. Agent(model:opus) to block Opus subagents." This is a first-party feature announcement, not a blog post.
- **IndyDevDan** — "Claude Fable 5 BANNED: The First Model Agentic Engineers DON'T NEED" (June 15, 2026): https://www.youtube.com/watch?v=D1BHGv4gB6c — ran Fable 5, Opus 4.8, and Sonnet 4.6 across 15 identical full-stack application specs in their own agent sandboxes. Results: Sonnet cost $55 and matched Opus ($91) on 4 of 6 task types; Fable cost $200 and beat Opus meaningfully only on the two hardest multi-agent tasks. Quote: "On about 80% of these tasks, the sibling models did the job at a fraction of the price." Specific dollar figures and live URLs provided, not just impressions. Core framing: "price per intelligent agent hour" — the new unit of measure, not price per token.
- **Anthropic's Fable 5 system card** (referenced in the IndyDevDan video): internal multi-agent benchmarks show accuracy scaling with compute but cost scaling too — Anthropic's own conclusion is that the right tier depends on task complexity.

**Evidence it's real:**

The `Tool(param:value)` feature is in the official Claude Code GitHub changelog for v2.1.178, timestamp 2026-06-15T21:35:55Z. I fetched the release page directly and read it. No intermediary.

The IndyDevDan benchmark is self-run (not peer-reviewed) but methodologically specific: same 5 specs, 3 model tiers, 15 total applications, public URLs. Cost numbers ($55 / $91 / $200) and token counts (700K / 700K / 1M) are stated explicitly and are independently checkable via the receipts he shows. The six application types ranged from simple (LLM price index clone, Hacker News clone, sklearn classifier) to complex (PI documentation chat agent, multi-agent chat room with embedded agent IDE). Model differences only appeared on the two hardest tasks. This matches what Cloudflare's multi-agent review benchmarks showed (covered June 14): tier selection matters most at the tail of task complexity.

The same v2.1.178 release also added "Improved auto mode: subagent spawns are now evaluated by the classifier before launch, closing a gap where a subagent could request a blocked action without review." This pairs directly with the new permission syntax — together they make the permission system actually enforceable for subagent tiers.

**Why it matters for us:**

Kyle's podcast pipeline is a multi-step agent chain with very different complexity profiles per step:

- **Beat reporters** (7 beats × ~150K tokens each = ~1M tokens/episode): Mostly reading transcripts, summarizing, and writing in a fixed voice. This is the workload IndyDevDan's benchmark says Sonnet handles within 5% of Opus. Currently these sessions default to whatever model is configured — likely Sonnet 4.6 already, but without enforcement, a beat reporter that spawns its own subagents could escalate.
- **Assemble-episode**: Editorial ordering, intro/outro writing, connecting the episode narrative. More creative/complex. Sonnet or Opus appropriate.
- **QC step (3-skeptic adversarial panel)**: Each skeptic agent runs a focused adversarial pass. Currently spawned as subagents — a natural place to enforce Sonnet to keep QC costs predictable rather than letting each skeptic pick a model.
- **COS / dispatcher tier**: The highest-complexity orchestration. Fable/Opus appropriate when available.

The new permission syntax makes it possible to encode these tiers explicitly in `.claude/settings.json` rather than relying on session defaults. This is configuration, not code — it survives pipeline changes and future Claude Code upgrades. It also closes the cost leak where any step can implicitly spawn an Opus subagent.

The "price per intelligent agent hour" framing is practically useful too. It's the right thing to say on-air about why the episode still sounds the same even though the pipeline now uses Sonnet for most beats: you're not paying for model prestige, you're buying time from the model that can do the job fastest at the task complexity you're actually dealing with.

**Build sketch** (an agent could run this cold from this file):

1. **Audit current model usage**: Add a log step to `generate-episode.sh` that captures which model each beat reporter session resolves to. Check if any beat subagents are currently escalating to Opus. (`ANTHROPIC_LOG_LEVEL=debug` or check Claude Code's session transcript.)

2. **Encode tier rules in project settings**: In `/Users/kylekillen/brainrot-radio/.claude/settings.json`, add permission rules using the new syntax:
   ```json
   {
     "permissions": {
       "deny": [
         "Agent(model:fable)",
         "Agent(model:claude-fable-5)"
       ],
       "ask": [
         "Agent(model:opus)",
         "Agent(model:claude-opus-4-8)"
       ]
     }
   }
   ```
   This blocks Fable spawns (cost/availability guard) and requires approval for Opus spawns — so beat reporters can only auto-spawn Sonnet or Haiku subagents without human review.

3. **Test the QC skeptics at Sonnet**: Run `/qc-episode` on a recent script with the Opus deny rule active. Check whether the 3 skeptics surface real issues or whether the adversarial pass degrades. If QC at Sonnet is equivalent, make Opus deny permanent for the QC step.

4. **Test the lightest beats at Haiku**: Entertainment and sports beats are lower editorial complexity (more summarization than judgment). Try running those beats with `Agent(model:haiku)` forced. Check output quality. If comparable, configure those beats to use Haiku.

5. **Document the tier map**: Once tested, write the tier routing into `.claude/context/architecture.md` so future sessions know the intended cost structure. The build-pitches file is the record; architecture.md is the operating spec.

Worth watching if Kyle ever wants to mix Claude with non-Anthropic models at the orchestration level, but not today's pitch.

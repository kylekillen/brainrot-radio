# Build-Pitch of the Day — 2026-07-02

## Pitch 1: Code-graph MCP + PreToolUse grep-augmentation for dispatched coding workers

**Technique.** Replace grep-then-read-the-whole-file exploration with a persistent, tree-sitter-built knowledge graph of the codebase (functions/classes/imports as nodes, calls/references as edges). A Claude Code `PreToolUse` hook intercepts every `Grep`/`Glob` call and silently injects the matching graph nodes (call chains, blast-radius, cross-file relationships) alongside the normal grep result — so the agent gets structural context for free without having to remember to call a special tool. Indexing a repo takes seconds to minutes (even the Linux kernel, 28M LOC, in ~3 minutes) and re-indexes incrementally on change.

**Who's doing it.** Demoed in "I was giving my coding agent context the wrong way..." (AI Jason, published 2026-06-30) — https://www.youtube.com/watch?v=iWRmtPdFbGw — showing a real before/after on a monorepo: 11K vs 38K tokens for a "trace this flow" question, 33K vs 64K tokens for a "what breaks if I change this" follow-up (roughly 2x reduction on his own repo). The underlying open-source project is DeusData/codebase-memory-mcp — https://github.com/DeusData/codebase-memory-mcp.

**Evidence it's real.** Cross-checked beyond the one video/demo:
- **Independent competing implementations of the identical pattern** (graph-indexed codebase + PreToolUse hook that augments grep): `colbymchenry/codegraph` (56.9K GitHub stars, pushed today), `CodeGraphContext/CodeGraphContext` (3.9K stars, active), `tirth8205/code-review-graph`, and "Graphify" (covered independently on dev.to/CLSkills). Four+ unrelated teams converging on the same architecture is a strong "this is a real category, not one creator's hype" signal.
- `DeusData/codebase-memory-mcp` itself: 24.2K stars, 1,777 forks, 199 open issues, pushed as recently as today (2026-07-02) — actively maintained, not abandoned.
- A cited research preprint, *"Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP"* (arXiv:2603.27277), reports 83% answer quality, 10× fewer tokens, 2.1× fewer tool calls across 31 real-world repos — an independent, benchmarked number set, not just the vendor's own claim (README separately claims 99.2% token reduction on a 5-query test: ~3,400 vs ~412,000 tokens).
- The hook design pattern (structurally non-blocking, injects `additionalContext`, never touches `Read`) matches Anthropic's own documented `PreToolUse` hook mechanics (code.claude.com/docs/en/hooks) — it's using the harness the way it's meant to be used, not a hack.

**Need it serves.** Optimization — dev-loop/cost/latency (explicit need d). Every fleet coding worker (dispatcher/PR-reviewer loop, Fleet Optimizer's own builds, delegate-skill workers) currently explores multi-repo codebases (observer-system, brainrot-radio, fleet-optimizer, claude-skills, trading bots) via grep-then-read, which is exactly the token-hungry pattern this replaces. This is distinct from the credit-resilience plan's existing model-tier-switching offload work (Z.ai/GLM, local Ollama) — it cuts token *consumption per task*, not the per-token price, so it compounds with those moves rather than duplicating them. Serves priority **(2) AI businesses — the multi-agent unlock**: cheaper, faster per-worker exploration means more parallel dispatched agents fit inside the same monthly credit cap before hitting the caps that blinded the money monitor twice (06-16/06-18).

**Whole-fleet leverage.** Repo-agnostic, zero-config-per-repo (auto-indexes), applies to every coding-capable worker in the fleet at once — a multiplier on dev-loop cost, not a single-project fix.

**Build sketch (an agent could pick this up cold).**
1. Spike on one repo first (recommend `fleet-optimizer` or `observer-system` — the ones with the heaviest multi-file dispatch churn), NOT a money-path repo.
2. Read `install.sh` at https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh **before** piping it to bash (it's a one-line `curl | bash` installer — verify contents first per standard supply-chain hygiene; it installs a single static binary, no runtime deps).
3. Run `codebase-memory-mcp` install for that repo's Claude Code config; confirm it registers the MCP server + the `PreToolUse` hook in `.claude/settings.json` (or the equivalent project settings) without touching any other hook already wired (PreCompact/Stop/SessionStart are already in place — see 2026-06-27 Fleet Optimizer note).
4. Verify indexing completes and a `search_graph`/`trace_path` query returns something sane.
5. A/B one real dispatch prompt (with vs without the graph augmentation) and log the token delta, the same way the video's demo did — that's the artifact that proves or kills the pitch for this fleet's actual repos before rolling it out further.
6. If it holds, extend to `observer-system`, `claude-skills`, and `brainrot-radio`; leave trading-bot repos for a separate, explicit go/no-go given the money-adjacency (indexing itself touches no money path, but flag it before wiring in `~/mojo-daemon`).

**Status: pitched**

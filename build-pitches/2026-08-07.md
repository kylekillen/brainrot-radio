## Pitch 1 — Prune the fleet's always-loaded CLAUDE.md files; Anthropic's own tooling already does the hard part, and one fleet file is already over their stated line-count ceiling

**Technique.** CLAUDE.md/global-rules files are loaded into *every* session's context, in full, on every turn — unlike skills or subagents, which load on demand. Anthropic's own guidance: "target under 200 lines per CLAUDE.md... longer files consume more context and reduce adherence." Boris Cherny (Claude Code's creator) went further at YC Startup School 2026: for people not building agentic products, delete your CLAUDE.md, skills, and hooks every six months and see what the model does without them — for Opus 5 specifically, Anthropic "strongly recommends" testing whether the old instructions are even still needed. Internally, Anthropic calls this **ablation**: delete the whole system prompt, then add lines back one at a time and measure the impact of each — closer to an eval than a vibe check.

**Who's doing it.**
- Cole Medin, ["The Creator of Claude Code Said to Do What Now?!"](https://www.youtube.com/watch?v=VnyGs43eiAA) (Claude Lab feed, this week) — plays the actual YC clips of Boris Cherny, then runs his own controlled A/B on his own large codebase (Archon, ~1,000-line CLAUDE.md) comparing full-rules vs. fully-stripped, across two axes: architectural judgment calls and project-specific conventions.
- Corroborating press on the same Cherny quote: [Rohan Paul on X](https://x.com/rohanpaul_ai/status/2082695402953031825), [BigGo Finance](https://finance.biggo.com/news/954a98de-8b79-429f-bd7e-761c27a3b210), [Medium / Data Science in Your Pocket](https://medium.com/data-science-in-your-pocket/delete-your-claude-md-asap-says-claude-code-creator-c72bd23f1086) — same quote, same YC Startup School 2026 source, independently transcribed.

**Evidence it's real.** Cross-checked directly against Anthropic's own current docs, not just secondhand summaries:
- [code.claude.com/docs/en/memory](https://code.claude.com/docs/en/memory): "**Size**: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." And: "**My CLAUDE.md is too large** — Files over 200 lines consume more context and may reduce adherence... The `/doctor` checkup **proposes trims for a checked-in CLAUDE.md**: it cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and **keeps pitfalls, rationale, and conventions that differ from tool defaults**. The trim check requires Claude Code v2.1.206 or later."
- Kyle's installed Claude Code is **v2.1.223** — the trim-check feature is already live, no upgrade needed, no custom tooling required.
- Cole Medin's own empirical result has real nuance, not a blanket "delete everything": in his A/B, the stripped-bare CLAUDE.md performed *equally well* on hard architectural calls but **broke on project-specific conventions** (test registration patterns, import style) — confirming Anthropic's docs almost exactly: keep "pitfalls, rationale, and conventions that differ from tool defaults," cut what the model can already derive or no longer needs.
- Checked it isn't already a fleet practice: `/doctor` has been run before in this fleet (`observer-system/STATUS.md`, 2026-06-09, a permissions-warning fix), but never for the CLAUDE.md trim-check specifically — that feature line didn't exist as a fleet practice before today's check.
- **Measured it against the fleet's own files rather than trusting the theory in the abstract:** `~/fleet-optimizer/CLAUDE.md` is **227 lines** — already over Anthropic's own 200-line ceiling, on the one repo that runs the fleet's own optimization/audit loop, multiple times a day. `~/.claude/CLAUDE.md` (global, loaded into **every session on the machine**, every role, every project) is 180 lines — under the line but close. `observer-system/CLAUDE.md` 154, `brainrot-radio/CLAUDE.md` 104, `mojo-daemon/CLAUDE.md` 62 — all comfortably under, for comparison.

**Need it serves.** Directly hits the loudest recurring pain in `STATUS.md`: the credit-cap gate has read `over` for three straight weeks (1.53x → 1.92x → 2.30x → 3.50x), stalling the Fleet Optimizer's own build queue. This isn't a replacement for `credit-resilience-plan.md`'s offload/PAYG-key moves — it's a same-day, zero-infrastructure companion: every token shaved off an always-loaded CLAUDE.md is a token saved on *every single turn of every session that loads it*, which for the global file (180 lines) means every role, every project, every day. Priority 2 (multi-agent collaboration carrying work without Kyle) benefits too: Anthropic's own docs state oversized CLAUDE.md files "reduce adherence" — a bloated global-rules file makes every delegated worker in the fleet *less reliable* at following the rules that matter, not just more expensive.

**Whole-fleet leverage.** Not project-specific — it's the one layer every role in the fleet shares (`~/.claude/CLAUDE.md`), plus the file that runs the fleet's own weekly audit (`fleet-optimizer/CLAUDE.md`, already over Anthropic's stated ceiling). Same tool (`/doctor`), same afternoon, applies uniformly across every repo Kyle's fleet touches — the exact "cross-cutting beats single-project polish" shape this beat is supposed to hunt for.

**Build sketch.**
1. Run `/doctor` inside `~/fleet-optimizer` first (it's the one file already over the 200-line guidance) and review the proposed trims — don't auto-accept; per Cole Medin's own result, only cut content the model can already derive from the codebase or general practice, and explicitly keep anything that's a fleet-specific convention, a past-incident rationale, or a rule this fleet has been burned by before (e.g. the "always fail loudly," "measure before quoting effort," and burn-cap-gate rules already in there — those are exactly the "differs from tool defaults" category Anthropic says to keep).
2. Repeat on `~/.claude/CLAUDE.md` (the global file) — highest leverage since it's loaded into every session on the machine, but also the file where a bad cut would misfire fleet-wide, so this one specifically should get a human read-through (Kyle or a peer role) before committing, not just an auto-accept of `/doctor`'s proposal.
3. Spot-check with a real before/after task on a non-critical repo (e.g. re-run a recent brainrot-radio or observer-system task with the trimmed file vs. the original) to catch any adherence regression before rolling the trim out further — matches this fleet's own "positive-control before trusting it" discipline already visible in `STATUS.md`.
4. Leave skills, subagent definitions, and hooks alone for now — both Cole Medin's testing and Anthropic's own load-order docs (skills load on demand, not at every turn) say the leverage is concentrated in the always-loaded CLAUDE.md layer, not there.

**Status: pitched** (fully auto-buildable — no trading/money logic touched; `fleet-optimizer/CLAUDE.md` should get a Kyle/peer read-through before merging since it governs the fleet's own audit behavior, but that's ordinary review discipline, not a money decision).

## Pitch: harden "spend tokens like money" from a prose wish into a harness-enforced layer

**Technique.** Layer a structured system-prompt file — named positive/negative behavior
patterns, short-code reference points, hard operational scope boundaries, and prompt
aliases (e.g. "compress this," "explain like I'm 18") — on top of Claude Code's built-in
`Concise` output style, delivered to headless fleet workers via `--append-system-prompt-file`
and reinforced with a `UserPromptSubmit` hook. The output style alone only strips
conversational preamble/narration; it doesn't touch substance-level verbosity (hedging,
repeated framing, "load-bearing"-style tics, unsolicited scope creep, self-credited commit
messages) — and per independent testing, prose-only instructions (which is exactly what
Kyle's current enforcement is — a paragraph in CLAUDE.md) measurably decay over long
sessions, while hooks don't.

**Who's doing it.**
- IndyDevDan, ["FIXING Opus 5: PROOF that Prompt Engineering IS NOT DEAD"](https://www.youtube.com/watch?v=S_QdQ1G4GlU)
  (published within the last 7 days) — live demo of exactly this: a four-section system
  prompt (purpose → positive/negative patterns → reference points → hard operational
  boundaries → aliases → in-context-distillation examples), applied via
  `--append-system-prompt-file`, cutting response time from 43s→22s and visibly reducing
  output tokens on identical prompts, run side-by-side with a comparison harness (`herdr`).
  Companion repo: [`disler/fixing-smartass-opus-5`](https://github.com/disler/fixing-smartass-opus-5)
  (the actual `sr_opus_5_system_prompt.md` artifact + `justfile` compare recipes).
- Independently, [Botmonster Tech, "Make Opus 5 less verbose with an output style and a
  hook"](https://botmonster.com/ai/make-opus-5-less-verbose/) — converges on the same
  output-style + hook combination from a different angle, explicitly states "hooks provide
  stronger enforcement than memory files, though even hooks experience decay as session
  length increases," and cites two named external benchmarks: Anthropic's "Laconic mode"
  testing (62.1% word-count reduction under brevity instructions) and a blind-judged
  "Attention Control" eval over 24 cases (+2.056 concision, +1.201 language, +0.535
  actionability, ~1/3 shorter replies on average).

**Evidence it's real.** Two independent creators, different audiences, converging on the
same mechanism within days of each other, both anchored to Anthropic's own official fix
for the same complaint — Claude Code v2.1.237 (2026-08-20) shipped a built-in "Concise"
output style specifically because Opus 5 "leads with results and skips preamble" was a
widely-reported problem (verified via the GitHub releases changelog directly, cross-checked
against three independent tech-blog writeups of the same release). The quantitative claims
(62.1% word reduction, +2 concision score) trace to a named benchmark, not just anecdote.

**What's already adopted vs. what isn't.** Checked `~/.claude/settings.json` — Kyle's fleet
already has `"outputStyle": "Concise"` set globally, so the baseline harness fix from
2.1.237 is live. But grepping `~/observer-system`, `~/brainrot-radio`, and
`~/fleet-optimizer` for `append-system-prompt` / a `UserPromptSubmit` hook turned up
nothing — the only configured hooks are `Stop` hooks (auto-commit, voice notes, etc.). The
deeper enforcement layer both sources describe — the one shown to survive long sessions —
is genuinely unbuilt.

**Need it serves.** Priority 3-adjacent and cross-cutting: less output-token burn per
headless worker narrows the odds of the podcast/fleet's shared Claude Max pool starving the
trading sentinel again (the exact failure mode `credit-resilience-plan.md` documents from
06-16/06-18). Also directly serves priority 1 (protecting Kyle's attention): every STATUS.md
entry, digest, and delegated report he reads gets shorter and more scannable without losing
substance, and it does so by fixing a problem Kyle has already named himself, in his own
global instructions.

**Whole-fleet leverage.** One shared artifact (a system-prompt file + a lightweight hook),
reused by every headless worker/daemon in the fleet, converts a prose-only wish that's
proven to decay over long sessions into a harness-enforced constraint — small one-time
build, compounding effect on both token spend and Kyle's reading load.

**Build sketch.**
1. Adapt (don't copy verbatim) `sr_opus_5_system_prompt.md`'s structure into a fleet-shared
   file, e.g. `~/.claude/system-prompts/lean-senior.md`, seeding the positive/negative
   pattern lists from Kyle's own "spend tokens like money" paragraph in his global
   CLAUDE.md plus the specific tics he's already flagged (no marketing voice, no padding,
   no narrated tool calls, no restating what was just done).
2. For headless fleet invocations (`generate-episode.sh`'s `claude -p ...` calls,
   observer-system daemons, dispatcher/worker spawns), add
   `--append-system-prompt-file ~/.claude/system-prompts/lean-senior.md`.
3. Add a lightweight `UserPromptSubmit` hook to `~/.claude/settings.json` that echoes a
   one-line brevity reinforcement (mirroring Botmonster's approach), so the rule survives
   long sessions instead of decaying as CLAUDE.md-only prose does.
4. Validate with a before/after comparison on 2-3 real fleet tasks (a beat-reporter run, a
   STATUS.md digest write) measuring output tokens and wall-clock — the same discipline
   IndyDevDan's `herdr` compare loop uses — before rolling out fleet-wide.

**Status: pitched.**

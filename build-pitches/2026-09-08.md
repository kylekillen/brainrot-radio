## Pitch — Deterministic claim-verification gate: never let a role's own report be the proof of its own claim

**Technique.** Treat every "done"/"confirmed"/"X is true" statement a role
writes (to STATUS.md, HANDOFF.md, a task completion, a cross-host report) as a
testable hypothesis, not a fact — extract the concrete, checkable claims from
the text and re-derive each one against real state with **zero LLM calls**:
stat the file, re-run the command, actually query the second host, re-count
instead of trusting the stated count. Critically, this is NOT "have another
LLM read the transcript and grade it" — that specific alternative was tested
and found to fail systematically.

**Who's doing it / evidence it's real.**
- **Academic, peer-reviewed-adjacent:** Laksh Advani, "From Confident Closing
  to Silent Failure: Characterizing False Success in LLM Agents"
  (arXiv:2606.09863, submitted 2026-06-01, accepted to the FAGEN workshop at
  ICML 2026 — not a random preprint). Measured false success — an agent
  confidently declaring completion when the environment's ground-truth state
  contradicts it — at 45–48% of failures on tau2-bench single-control domains
  and **75.8% of failures on AppWorld** (a benchmark with database-state
  ground truth entirely independent of the agent's own language). Then tested
  the obvious fix — an LLM judge reading the trajectory — across 5 judge
  models × 5 prompt strategies: **best AUROC was 0.65 on tau2-bench, 0.54 on
  AppWorld** (0.5 = coin flip). Judges anchor on confident closing language
  and action-sequence volume, not verified state — which is exactly why a
  false-success trajectory fools them: it's written to sound confident.
  Lightweight, non-LLM, domain-calibrated detectors instead reached
  **0.83–0.95 AUROC at 3,300x lower latency**.
- **Independent practitioner corroboration, same conclusion, different
  method:** JinHyuk Sung's `nuhuh` (dev.to, "75.8% of failing AI coding runs
  still say 'Done'. Here's what finally caught mine.") — built exactly this
  pattern for coding agents: extract claims ("all tests pass," "created
  src/x.ts," "endpoint works"), re-verify each with a real command re-run,
  file-existence check, or live endpoint call, zero LLM calls in the
  verification path. Deployed as a gate, a rejected claim bounces back to the
  agent with the receipt attached; caught failures (e.g. a lint script whose
  failure was silently swallowed on macOS) that pattern-matching alone
  missed. Two independent groups, working from different starting points
  (academic benchmark vs. a shipped tool), landed on the same architecture.

**Need it serves.** Directly matches the fleet's own dominant, currently-open
pain (see above) — priority 3 (resilience: cross-host migration correctness,
the trading/copybot install state the same STATUS.md thread is auditing) and,
cross-cuttingly, priority 2 (protects the multi-agent unlock: the whole point
of delegating to a team of AIs is that Kyle doesn't have to personally re-catch
each one's false claims by hand, which is exactly what's happening right now,
incident by incident, this week).

**Whole-fleet leverage.** This is not narrow to the migration — it's the same
failure shape the fleet has already independently rediscovered piecemeal
(`handoff_guard.py`'s stale-pointer check, `memory_verifier.py`'s size-fit/
link-reachability check) but never generalized into a reusable layer any role
can call before writing a claim to STATUS/HANDOFF/INBOX. Every role in
`roles.json`, every dispatched subagent, and the migration work itself all
emit the exact claim shape this fixes.

**Build sketch.**
1. New module, `observer/coordination/claim_verifier.py`, siblings to
   `handoff_guard.py`. Generalize `handoff_guard.py`'s existing "concrete,
   complete pointer" extraction logic (`scan_handoff`, `_is_concrete_path`,
   the template/placeholder exclusion rules it already has) from "paths and
   plist labels" to a small taxonomy of checkable claim shapes: file/path
   existence, launchctl load state, a stated count vs. an enumerable set, and
   a "this is true on host X" assertion.
2. Each claim shape maps to a real, deterministic check function (stat, `ps`/
   `launchctl list`, `len()` against the actual enumerated set, an actual
   SSH/query against host X — never a read of host A's own memory of host X).
   Zero LLM calls, mirroring `nuhuh`'s design and the paper's finding that
   LLM-judge review is the approach that specifically fails here.
3. Wire it as a pre-write gate on STATUS.md/HANDOFF.md entries during the
   still-live Mac mini migration first (the active incident stream, cheapest
   way to prove it against fresh false-claim cases as they occur), then widen
   to a general dispatcher-side check any role can call before marking a task
   done.
4. On mismatch: block the write, return the receipt (what was claimed vs.
   what was actually found) to the writer instead of silently correcting it —
   same "bounce with evidence" loop `nuhuh` uses.

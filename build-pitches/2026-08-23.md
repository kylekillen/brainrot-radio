## Pitch: two shipped Claude Code releases directly patch the fleet's own documented native-messaging blockers — the assessment that ruled the feature out is now two weeks stale

**Technique.** The fleet already has a dated, specific verdict on Claude Code's native
`SendMessage`/`ListAgents` cross-session bus: `~/.observer/wiki/agent-os/memory` entries
`[[native-bus-is-live-only-pid-addressed]]` and
`[[live-fleet-sessions-are-not-mutually-discoverable]]` (both measured 2026-08-09, full
write-up `~/.observer/wiki/agent-os/native-cross-session-messaging-assessment.md`, same
date) concluded it's an *additive fast path only, never a replacement* for the homegrown
`agent-msg.sh`/`wake_role.py`/`role_mail_router.py` mail system, for two measured reasons:
(a) a message to a session running `--dangerously-skip-permissions` (every autonomous role
desk in the fleet) is **held silently** pending an approval nobody is present to give — the
sender is told nothing; (b) the fleet's live sessions are barely ever co-live at the same
moment, so a synchronous request/response mostly can't complete anyway ("the fragility we
keep patching in `agent-msg.sh` is not a transport problem — the fleet is almost entirely
store-and-forward between sessions that are never alive at the same moment").

Since that 08-09 verdict, Anthropic shipped fixes for **both** named blockers:
- **v2.1.224 (Aug 7) → v2.1.232 (Aug 13):** `crossSessionInbound` became a documented,
  settable config value (`accept` / `hold` / `refuse`), settable per-session via
  `--settings` at dispatch time — precisely so a long-running unattended worker can opt in
  to accept inbound messages instead of silently parking them. This is the exact fix for
  the "Held peer message... not delivered... set `crossSessionInbound` to accept" failure
  the fleet measured on 2026-08-15 against skip-permissions role desks.
- **v2.1.236 (Aug 19):** `notify_when_idle` added to cross-session `SendMessage` — "ask
  another Claude Code session on this machine to send one notice when it next goes idle
  (opt-in, one-shot, no polling)." This converts "both parties must be alive at the same
  moment" into an event-driven wake, which is exactly the axis the 08-09 assessment flagged
  as the fleet's real bottleneck (a near-empty co-live population, not a transport bug).

**Who's doing it.** Anthropic's own changelog, [code.claude.com/docs/en/changelog](https://code.claude.com/docs/en/changelog)
— v2.1.224 (self-hosted runners + cross-session `SendMessage`), v2.1.232 (`@`-mention
routing, `crossSessionInbound` config rows, subagent forking on by default), v2.1.235
(burst-refusal guardrail so messaging can't silently become a dropped-message queue), v2.1.236
(`notify_when_idle`). Independently corroborated by DevelopersIO's dated write-up of the
2.1.236/2.1.237 releases (dev.classmethod.jp, "Claude Code v2.1.236~v2.1.237 Major Updates")
and a same-window third-party piece framing exactly these two settings as the ones that make
the native bus usable for unattended workers ("Claude Code Sessions Can Message Each Other:
5 Ways, Ranked").

**Evidence it's real.** Primary source is Anthropic's own shipped-product changelog — the
most verifiable category available, not a demo or a blog claim. Cross-checked the version
numbers/dates/feature descriptions via three independent secondary write-ups that landed on
the same specifics, and confirmed the fleet's own prior measurement (the 08-09/08-15 memory
entries) named exactly these two gaps as blocking — meaning the fix maps 1:1 onto a
documented internal failure, not a speculative improvement.

**Need it serves.** Priority 2 (AI businesses / the multi-agent-without-Kyle unlock),
directly on the fleet's own diagnosed weak point: role-to-role handoff reliability. Doesn't
touch credit/cost (Priority-adjacent but not the live pain this week) and isn't a trading
change.

**Whole-fleet leverage.** A `--settings` flag change at role-desk dispatch time plus wiring
one new SendMessage parameter into an existing wake path is near-zero build cost and doesn't
touch the durable `INBOX.md` audit trail (which stays the system of record) — pure upside,
and it re-tests a two-week-stale internal assessment against real, now-different platform
capability rather than leaving it to silently rot as "checked, ruled out."

3. Update `~/.observer/wiki/agent-os/native-cross-session-messaging-assessment.md` (dated

4. Keep the fleet's own guardrail intact: `agent-msg.sh`'s durable append, spawn-on-message,

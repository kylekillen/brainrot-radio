## PITCH 1 (Primary): Headroom — Wrap Claude Code to Cut Ingest Token Costs 60-92% and Auto-Improve CLAUDE.md from Failed Sessions

**Technique:** Headroom is an open-source middleware layer that wraps Claude Code (and any other coding agent) and compresses everything the agent *reads* before it reaches the LLM — tool outputs, JSON feeds, transcripts, logs, conversation history. Compression ratios of 60-92% on typical agent inputs with no accuracy degradation on benchmarks. One command installs it: `headroom wrap claude`. No pipeline code changes required. A second feature, `headroom learn`, mines your failed agent sessions and generates specific CLAUDE.md improvement suggestions (e.g., "load deferred tool schemas at session start — saves 8,000 tokens per session").

**Who's doing it:**
- **Tejas Chopra** (senior engineer at Netflix) — built and open-sourced Headroom in January 2026. Repo: https://github.com/chopratejas/headroom (Apache 2.0, 23,400+ GitHub stars as of June 2026)
- **Matthew Berman** demonstrated it live in his June 12, 2026 video "You NEED to try these open-source AI projects RIGHT NOW": https://www.youtube.com/watch?v=zjFE-dBzP_E — showed both `headroom wrap claude` in a real Claude Code session and the `headroom learn` output in action. The specific suggestion the tool surfaced was: *"It can save 8,000 tokens per session by loading deferred tool schemas."* (directly applicable to Kyle's setup, which uses deferred tool schema loading via ToolSearch)
- **extraheadroom.com** — commercial desktop wrapper by a separate team (https://github.com/gglucass/headroom-desktop), built on the open-source CLI. 229 active developers, 13.8 billion tokens saved collectively. Local-only: "Your prompts never touch our servers."

**Evidence it's real:**
Benchmark results from the GitHub README, independently verified across multiple sources:
- **GSM8K** (math reasoning, 100 samples): 0.870 baseline vs. 0.870 with Headroom — zero degradation
- **TruthfulQA** (factual QA): 0.530 baseline → 0.560 with Headroom — marginal *improvement*
- **SQuAD v2** (reading comprehension): 97% accuracy at 19% compression
- **BFCL** (tool-use benchmark): 97% accuracy at 32% compression

Real-world savings from extraheadroom.com:
- Build logs (200 lines): **93.9%** token reduction
- JSON arrays (100-500 items): **83-90.6%** savings
- Shell output (200 lines): **85.5%** savings
- Multi-tool agent sessions (memory leak investigation): **61%** savings

Compression mechanism is documented and specific: a `ContentRouter` detects content type and selects one of three compressors — `CodeCompressor` (AST-aware, handles Python/JS/Go/Rust/Java/C++), `SmartCrusher` (universal JSON compression), and `Kompress-base` (a HuggingFace model trained on agentic traces for text). A `CacheAligner` stabilizes prompt prefixes to maximize provider KV-cache hit rates. All components are open-source and inspectable.

`headroom learn` is documented in the README and shown in the Berman video. It analyzes session logs for failures and produces CLAUDE.md improvement suggestions for human review before applying — not fully automated, but the review step is by design (you want to vet CLAUDE.md edits).

Corroborated independently by: Alphamatch.ai (blog analysis), Dashen Tech (technical guide), DEV Community writeup, buildthisnow.com — all treating it as a real tool, not hype.

**Why it matters for us:**
The two most token-hungry steps in Kyle's podcast pipeline are `/generate-brief` (reads ranked RSS/YouTube/podcast JSON) and `/run-beat-reporters` (each beat reporter loads multiple long transcripts). These are precisely the workloads Headroom excels at: JSON arrays, long text transcripts, tool outputs. If each beat reporter session currently burns ~150K tokens, 73% compression saves ~110K tokens per beat × 7 beats per episode = ~770K tokens per episode, every day. At current Sonnet/Opus pricing, that's real money compounding daily.

The `headroom learn` angle is specifically on-point: the pipeline has documented failure modes (wrong day-of-week in the show header, dedup misses, QC failures requiring re-runs). Running `headroom learn` after a week of sessions would surface patterns like "your ingest JSON is being passed in full — strip to top-10 scored fields before passing to beat reporter" or structural CLAUDE.md improvements Kyle's current memory system doesn't catch because the memory system records preferences and project context, not technical session failure patterns.

There's also a deferred-schema angle unique to Kyle's setup: the system-reminder about deferred tools (`ToolSearch` required before calling `WebSearch`, `WebFetch`, `TaskCreate`, etc.) means every session that doesn't pre-load those schemas burns tokens loading them lazily. The Berman demo showed headroom learn surfacing exactly this pattern unprompted ("load deferred tool schemas at session start — saves 8,000 tokens per session"). This is a direct CLAUDE.md improvement suggestion for the brainrot-radio project.

**Build sketch** (an agent could execute this cold from this file):
1. `source venv/bin/activate && pip install headroom` — installs the CLI
2. Run one full episode generation with Headroom wrapping just the beat reporter step: `headroom wrap claude -- claude -p "$(cat .claude/commands/run-beat-reporters.md)"`. Don't change `generate-episode.sh` yet.
3. After the run: `headroom perf` to see actual compression ratios on brainrot-radio's specific data (RSS JSON, YouTube transcripts, podcast transcripts). If savings are >40%, proceed.
4. Edit `generate-episode.sh`: wrap the `run-beat-reporters` and `generate-brief` invocations with `headroom wrap claude --`. Leave `qc-episode` and `publish-episode` unwrapped for now (they don't read heavy external data).
5. After one week of wrapped sessions: `headroom learn` and review the CLAUDE.md suggestions. Apply anything that matches known failure patterns (dedup misses, deferred schema loading, day-of-week errors). Do not apply blindly — review each suggestion against the current CLAUDE.md before committing.
6. Optional: try the `--memory` flag on `headroom wrap` for the multi-turn `assemble-episode` step, which builds up the longest context in the pipeline.

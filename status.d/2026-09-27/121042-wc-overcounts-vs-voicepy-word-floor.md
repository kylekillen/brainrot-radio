### 2026-09-27 06:10 — `wc -w` on a script file overcounts voice.py's real render word count by ~70-100 words

When manually topping up a QC-cut script toward the 6,000-word render floor (same gap as `status.d/2026-09-25/173500-*` and today's `042755-*`/`113800-*`), don't trust `wc -w scripts/killen-time-*.txt` as the render-floor check — it counts each `[BASIL]`/`[BROOKE]`/`[TRANSITION]` tag as a word, but `voice.py`'s `parse_script()` strips tags before counting (`voice.py:213`). On today's 09-27 top-up this meant a `wc -w` of 6,040 was actually only 5,968 real words per `voice.py` — under the floor despite looking safely over it. Always verify with `python3 -c "from voice import parse_script; ..."` (sum `len(t.split())` over non-TRANSITION segments) before considering a top-up done, not the raw file word count.

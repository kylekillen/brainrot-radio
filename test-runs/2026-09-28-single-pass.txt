[BROOKE] Agents and Building With AI is our featured beat today. The through-line is cost per successful task and how effort controls are being treated as first-class knobs. Anthropic’s own docs now say to sweep effort per workload and use a “run cheap first, re-run failures harder” ladder. That’s the line that keeps showing up in the operator notes.

[BASIL] The Build Pitch of the Day is stop running every fleet worker at default effort. Claude now has an effort dial, low through max, and Anthropic’s documentation is explicit about sweeping it per workload. On Opus 5.5, which launched last week at $4/$20 per million tokens, the measured numbers on coding tasks show medium effort costs about 70% of high for roughly 2.5 points less accuracy, and low costs about a third. The low-first-then-escalate ladder hit about 97% pass at lower spend versus running everything high.

[BROOKE] Who’s saying it? Anthropic’s optimizing for cost and intelligence docs, Matthew Berman’s Opus 5.5 launch stream with an Anthropic Claude Code lead, and independent Artificial Analysis data: Opus 5.5 index scores of 42 at low, 51 at medium, 58 at max, with cost per task running from 55 cents to almost six dollars. An arXiv paper this month makes the same point: judge agents on cost per successful task, because more effort sometimes just adds cost.

[BASIL] The pitch is a config change, not a new system. Record effort per task, run a shadow bake-off of Sonnet 5 default, Sonnet 5 medium, Opus 5.5 low and Opus 5.5 medium on a hold-out set, scored by cost per landed PR, then set the winning default and a low-first escalation ladder in the sweeper. It’s tuning inside the Anthropic pool, different from last week’s rejected multi-provider idea.

[BROOKE] The honest caveats are real. Those benchmarks are vendor-run, cover Opus 5.5 and Fable rather than Sonnet 5, and measure SWE-bench-style coding, not PR review. So it’s a strong hypothesis, not a proven saving. The value is that it gives operators a measurable lever they can test without changing the agent graph.

[BASIL] That’s why it’s logged in the build-pitches folder for Kyle to greenlight. If the shadow bake-off confirms the cost curve, you get a default that’s cheaper on the easy tail and only spends when the task actually needs it. The broader lesson for multi-agent setups is to treat effort as a routing signal, not a moral setting.
